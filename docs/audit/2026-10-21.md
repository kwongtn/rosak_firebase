# rosak_firebase audit, 2026-10-21

Read-only audit of `rosak_firebase` at `cb70022`: code, UI/UX, accessibility, performance, security, SEO, tooling, tests and feature opportunities. **406 verified findings**, grouped into 9 themes. Each theme has its own detail file under [`2026-10-21/`](2026-10-21/); finding IDs link to their full write-up (problem, recommendation, verification notes and evidence).

## Executive summary

rosak_firebase is a disciplined codebase. Pure, well-specced utilities, a careful `graphqlResource` and polling layer, bounded keep-alive routing, deliberate per-route render modes, sanitised markdown, deny-by-default Firestore rules and a deterministic e2e harness are real strengths. The TypeScript already compiles under `--strict` with zero errors, so turning strict mode on is nearly free ([F073](2026-10-21/testing-tooling-and-code-quality.md#f073)). The problems are concentrated, and most are cheap to fix.

**Wrong data and broken flows that users hit today.**

- Public profiles show the viewer's own name, photo, email and phone instead of the owner's details. Logged-out visitors see "Anonymous" ([F026](2026-10-21/data-reliability-and-error-states.md#f026)).
- "Today" and the day headers on /insiden use UTC. From midnight to 8 am Malaysia time the page opens on yesterday, and link groups are a day early ([F010](2026-10-21/time-zone-and-date-correctness.md#f010), [F007](2026-10-21/time-zone-and-date-correctness.md#f007), [F081](2026-10-21/time-zone-and-date-correctness.md#f081)).
- A successful Extract leaves the chronology row disabled ([F009](2026-10-21/forms-uploads-and-sign-in-flows.md#f009)).
- Pressing Escape in the spotting form's vehicle picker closes the whole sheet and wipes the draft ([F030](2026-10-21/accessibility-and-keyboard-access.md#f030)).
- Vote buttons render as unstyled 16 px controls ([F011](2026-10-21/ux-content-and-visual-polish.md#f011)).
- Network failures on the three submit forms show no message ([F003](2026-10-21/forms-uploads-and-sign-in-flows.md#f003)).
- `graphqlResource` can throw from `data()` and `errors()`, and it drops the last good data when a refresh fails ([F033](2026-10-21/data-reliability-and-error-states.md#f033)).

**Server rendering and payload.**

- Server rendering of /gallery waits for a year-count aggregate. Locally that query took 26.5 s, against 0.6 s for the photos themselves ([F012](2026-10-21/performance-bundle-and-ssr-hydration.md#f012)).
- The home page mounts closed forms that add 137 KB of reference data to every HTML response ([F035](2026-10-21/performance-bundle-and-ssr-hydration.md#f035)).
- The line-details grid ships 10,672 mostly-zero rows (694 KB of TransferState) plus a desktop table that phones throw away ([F018](2026-10-21/performance-bundle-and-ssr-hydration.md#f018), [F051](2026-10-21/performance-bundle-and-ssr-hydration.md#f051)).
- The vehicle page downloads the whole fleet to show one vehicle ([F046](2026-10-21/performance-bundle-and-ssr-hydration.md#f046)).
- The build's "initial" total leaves out eagerly loaded shared chunks, so the real initial JS is about 3.5 times the reported size ([F072](2026-10-21/testing-tooling-and-code-quality.md#f072)).

**Security and privacy.**

- Angular 22.1.0 has high-severity SSR advisories. A lockfile-only update fixes them ([F015](2026-10-21/security-privacy-and-platform-hardening.md#f015)).
- The public API returns the coordinates of anonymous location reports. Photos under 9 MB keep their EXIF GPS data. Both need mostly backend fixes ([F043](2026-10-21/security-privacy-and-platform-hardening.md#f043), [F044](2026-10-21/security-privacy-and-platform-hardening.md#f044)).
- The SSR server sends no security headers ([F255](2026-10-21/security-privacy-and-platform-hardening.md#f255)).
- There is no consent gate for analytics, ads or Replay ([F257](2026-10-21/security-privacy-and-platform-hardening.md#f257)).

**Accessibility.** Icon buttons have no visible focus ring ([F001](2026-10-21/accessibility-and-keyboard-access.md#f001)). Sheets, the combobox, the gallery viewer and the calendar lack dialog semantics, ARIA and keyboard support ([F029](2026-10-21/accessibility-and-keyboard-access.md#f029), [F030](2026-10-21/accessibility-and-keyboard-access.md#f030), [F032](2026-10-21/accessibility-and-keyboard-access.md#f032), [F037](2026-10-21/accessibility-and-keyboard-access.md#f037)).

**Biggest opportunities:**

- one Kuala Lumpur time helper
- an accessible sheet primitive
- deferring forms and Sentry Replay out of the first load
- share metadata and an installable app ([F016](2026-10-21/ux-content-and-visual-polish.md#f016), [F202](2026-10-21/ux-content-and-visual-polish.md#f202), [F210](2026-10-21/feature-opportunities.md#f210))
- a rider-facing incident notice on the home board ([F077](2026-10-21/feature-opportunities.md#f077))

### Lighthouse

These numbers come from a sequential Lighthouse 12.8 run after the audit, using simulated mobile throttling unless the row says desktop. Read them as relative signals:

- The data came from a local backend.
- The bare Node SSR server does not compress responses.

- The machine was shared, and TBT varied by up to 2x between runs.

## Strategic initiatives

### Stop shipping data nobody sees

Closed sheets, zero-filled grids and blocking decorative queries dominate SSR time, HTML size and TransferState.

1. Mount the report and link sheets lazily (@defer or on open) and fetch reference data only when opened ([F035](2026-10-21/performance-bundle-and-ssr-hydration.md#f035), [F309](2026-10-21/performance-bundle-and-ssr-hydration.md#f309))
2. Drop addZero on the spotting grid and render the grid client-only or compactly ([F018](2026-10-21/performance-bundle-and-ssr-hydration.md#f018), [F051](2026-10-21/performance-bundle-and-ssr-hydration.md#f051), [F241](2026-10-21/performance-bundle-and-ssr-hydration.md#f241))
3. Make gallery SSR independent of the year-count query ([F012](2026-10-21/performance-bundle-and-ssr-hydration.md#f012))
4. Fetch only the needed vehicle and the report-form data on demand ([F017](2026-10-21/performance-bundle-and-ssr-hydration.md#f017), [F046](2026-10-21/performance-bundle-and-ssr-hydration.md#f046))
5. Slim the month query and the Insiden tab payload ([F038](2026-10-21/performance-bundle-and-ssr-hydration.md#f038), [F266](2026-10-21/performance-bundle-and-ssr-hydration.md#f266))
6. Lazy-load Sentry Replay, markdown, recaptcha and the Home store out of main ([F002](2026-10-21/performance-bundle-and-ssr-hydration.md#f002), [F120](2026-10-21/performance-bundle-and-ssr-hydration.md#f120), [F555](2026-10-21/performance-bundle-and-ssr-hydration.md#f555))
7. Remove maplibre from the tracker chunk and fix budgets to count shared chunks ([F272](2026-10-21/performance-bundle-and-ssr-hydration.md#f272), [F072](2026-10-21/testing-tooling-and-code-quality.md#f072))

## Method, coverage and limitations

**How the audit ran.** One orchestrated run of 58 agents, followed by a second pass of 16.

1. **Capture (4 agents).** A production SSR build of `cb70022` was served locally against the local Docker API. The agents produced:
   - 74 route screenshots (390 px and 1440 px wide, light and dark)
   - 60 interaction screenshots (menus, sheets, keyboard focus, reduced motion, offline, slow network, the admin console)
   - per-route metrics, including axe-core results
   - Lighthouse reports
2. **Audit (26 auditors).**
   - 11 code areas.
   - 7 cross-cutting sweeps: performance, accessibility, security, SEO/PWA/i18n, dependencies and tooling, test gaps, and feature opportunities.
   - 4 visual UX reviewers, working from the screenshots.
   - 4 follow-up auditors (areas `gap-1` to `gap-4`). A coverage critic found 4 blind spots: whether the methodology registry matches the real computation, signed-in journeys end to end, GraphQL operations against the live schema, and time-zone handling across the app. One follow-up auditor covered each.
3. **Verify.** Each auditor's batch went to an adversarial verifier that re-opened every cited location.
   - Of 602 raw findings, 345 were confirmed, 255 were partially confirmed and 2 were refuted. A partial confirmation means the verifier corrected the severity or the fix, and the correction is shown on the finding.
   - A synthesis pass merged 194 duplicates into the surviving finding (listed as "Also reported as") and grouped the rest into themes.
4. **Second check.** Two more reviewers re-checked each of the 31 high-severity findings, working independently.
   - One traced the code end to end and reproduced the claim where that was cheap, using curl, node under `TZ=Asia/Kuala_Lumpur`, or `npm audit`.
   - The other judged the user impact and the proposed fix.
   - None was refuted. 15 stayed high and 16 were lowered to medium. Their notes appear on each finding.

Capture, SEO/PWA, dependency and test-gap agents ran on Haiku. Auditors, verifiers and synthesis ran on Sonnet.

**Limitations.**

- The audit used local data on a local development backend, not production.
- Absolute timings (SSR time, GraphQL latency) were measured while many agents shared the machine, and the local API returned 16 gateway timeouts during the run. Treat the seconds as relative signals, and re-measure against staging before quoting them.
- The Lighthouse table comes from a separate sequential run. It used simulated mobile throttling, blocked third parties, and had no CDN compression in front of the bare Node server.
- The audit browser disabled CORS, because the local API allows only port 4200. It also blocked ads, analytics, Sentry and reCAPTCHA, so third-party cost is missing from the measurements.
- The Mapbox style was unreachable from the audit environment, so the tracker map numbers are not representative.
- Signed-in and admin pages were viewed only through the test-only `__e2eAuthOverride__`, with no real token, so their data loads failed by design. Signed-in journeys were reviewed from code instead (`gap-2`).
- The logged-out account panel and a public `/profile/<id>` page were not captured.
- Line references are to `cb70022` and will drift as the code changes.

**Evidence.** Screenshots, per-route metrics, Lighthouse reports, build stats and the capture scripts are kept locally in `.omo/evidence/audit-2026-10-21/`. That folder is gitignored and holds about 60 MB. Evidence paths in the findings point there.

**Reproducing the runtime setup.** Run `npx ng build --stats-json`, then `NG_ALLOWED_HOSTS=localhost PORT=4321 node dist/web/server/server.mjs`. The environment variable is needed because Angular's SSR host check rejects unknown hosts while `security.allowedHosts` is empty in `angular.json`.
