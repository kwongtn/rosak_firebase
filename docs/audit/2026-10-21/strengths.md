# Strengths noted by the auditors

Part of the [rosak_firebase audit, 2026-10-21](../2026-10-21.md). Raw notes from each auditor, kept as written.

- [home-data] Failure isolation is well designed and pinned by specs: the history, incidents and official-notices reads are lazy, opt-in per widget and kept out of hasError, isLoading and isRefreshing, so a broken chart cannot replace a healthy page.
- [home-data] Query variables are compile-time constants and the lines history is requested sorted in one linesStatusHistory call for every row, which keeps SSR TransferState reuse intact and avoids a sixteen-request fan-out; graphqlResource's deepEqual retention means an unchanged beat does not re-run the computed chains.
- [home-data] PollingSource pauses on visibilitychange, keeps a wall-clock deadline, refreshes immediately on return if the deadline passed, and resume() fixes the retained-route-injector re-entry trap with a spec.
- [home-data] The status utilities (status-confidence, network-summary, board-lines partition, passenger-status, feed-filter) are pure, total on absent input, share methodology-registry constants and have thorough specs; the four-group partition invariant is clear and tested.
- [home-data] The board's accessibility details are thoughtful in places: per-line aria-labels on repeated buttons, aria-expanded with aria-controls on rows, aria-pressed on filter chips, a skip link to the board, reduced-motion variants on every animation.
- [home-ui] The feed tab set is a correct ARIA tablist: roving tabindex, arrow/Home/End keys with wrap, aria-controls and aria-labelledby resolved by keeping inactive panels mounted with the hidden attribute, and a spec that pins it.
- [home-ui] HomeStore concentrates feed state well: one variables source for resources, load-more continuations and overlay reads, dedupeEdges merging so polling does not drop appended pages, a visibility-aware PollingSource, and a lazy gate on the Last Week and history reads.
- [home-ui] The submit box has thought-through validation: submit-gated errors, novalidate on the form, a tested pure normalizeFeedUrl, a role=alert inline error, and a duplicate path that records the upvote instead of failing.
- [home-ui] SSR integration is mostly deliberate: TransferState reuse through compile-time constant variables, a skip link to #line-board that works in both views, reduced-motion handling and a mobile bar that honours safe-area insets.
- [home-ui] The report chooser is a clean intent-first wrapper over existing sheets with a pure, tested ordering util (pinned, recent, severity) and honest empty and no-lines states; the sheet mount order invariant is documented and spec-pinned.
- [insiden-data] Backend authorisation is enforced server side, not just in the UI: incident/services/access.py (may_edit) and social_links.py (owner or admin) back the cosmetic can-edit utilities, which are small pure functions with specs and honest comments saying so.
- [insiden-data] The link form's occurredAt handling (link-occurred-at.util.ts and its spec) is a careful, well-documented treatment of naive Kuala Lumpur wall time and the tri-state update semantics, including never sending null accidentally. It is the model the incident form should adopt.
- [insiden-data] The data utilities (calendar-date, chronology-status, elapsed-time, incident-history-line, link-url) are pure, Angular-free, hand-formatted (no per-call Intl construction) and have colocated specs; the incident-to-form, chronology-list and extract-data utilities make the form logic unit-testable.
- [insiden-data] Mutation payloads are built from the full form state with deliberate guards against replace-not-patch data loss (echoed impactFactor, version for optimistic concurrency, tags always selected by the edit hosts), and the edit flow correctly chains submit for draft revisions.
- [insiden-data] The sheet-open hydration and reset guards are thoughtfully commented, and the existing specs cover create, edit, chained submit, backend rejection, version mismatch and Undo All for the incident form.
- [insiden-ui] VoteButtonComponent keeps vote math in a pure, tested util (vote-state.util.ts) and layers optimistic, server-acknowledged and host state so the server always wins, with rollback and a toast on failure; this fixed a real re-seeding bug and is well documented.
- [insiden-ui] Incident details markdown is sanitised by default (ngx-markdown calls sanitizeHtml unless the sanitizer is disabled, confirmed in the built bundle), and every external anchor uses target=_blank with rel="noopener noreferrer" while URLs go through Angular's href sanitisation.
- [insiden-ui] The link card's stretched-anchor design keeps interactive controls as siblings of the link, gives the overlay an explicit accessible name and moves chip explanations into sr-only text, with the reasoning recorded.
- [insiden-ui] Calendar date handling uses string-key comparison for incident coverage, a linkedSignal for the viewed month and a URL-driven selected date, so Back and Forward walk through days and the route reuses the component instance via the optional-param matcher.
- [insiden-ui] Lazy, per-incident loading of history and link continuation pages with inline retry (no failing sentinel loop), and graphqlResource's isLoading versus isFetching split with bounded exponential backoff, show good attention to failure states.
- [console] Pure, spec-covered utilities carry the hard logic: link-tree.util, link-queue-filter.util, link-status-input.util, same-minute.util, date-range.util and pending-incident.util each have a colocated spec, and the replace-not-patch trap on SocialMediaLinkInput is handled deliberately in one place (linkStatusInput).
- [console] Approve on the links queue is a carefully ordered two-write sequence with explicit partial-failure messaging, one reload, and a recursive subtree confirm before Hide; the spotting queue's bulk selection correctly handles checkbox vs row clicks with shift-range selection through the shared useBulkActions composable.
- [console] The links page already queues a reload that arrives mid-load and replays it from one finishLoading() choke point, and it snapshots the completeness flag before the first await, so the reorder gate cannot disagree with the rows on screen.
- [console] Route setup is solid: the console is RenderMode.Client, adminOnlyGuard awaits auth.whenReady, every leaf is guarded, redirects are pathMatch-correct, and console.routes.spec.ts covers the redirect and sibling-route behaviour.
- [console] Pending and links tables ship skeleton rows, aria-busy and an sr-only status, rejection requires a reason shown to the submitter, and external URLs use rel="noopener noreferrer" with Angular's default href sanitisation (no bypassSecurityTrust usage in scope).
- [spotting] Pure, tested helpers for the heavy logic: grid layout and data utilities, fleet-count chips, route patterns and vehicle search each have their own specs, which made the grid refactor into small presentational row components safe.
- [spotting] The keep-alive design is thoughtful and bounded: opt-in data: { reuse: true }, an LRU of 10 handles keyed by route-config and path params, scroll memory, and polling that pauses when the document is hidden or the page is not the active route.
- [spotting] graphqlResource gives every read SSR TransferState, exponential backoff capped at 3 minutes, a retry banner pattern and retainDataIfEqual so silent revalidation does not churn the DOM; most spotting sections use the retry banner and skeletons correctly.
- [spotting] The report form uses Signal Forms with a declarative schema and a validateTree cross-field validator, the station query is projected to primitives so Notes keystrokes do not re-issue it, and the compression-in-progress race was already identified and guarded.
- [spotting] The photo upload queue is persisted to IndexedDB and bounded with a PromisePool, which is a real resilience gain for users on unstable mobile networks.
- [tracker-gallery] Gallery first-page data is transferred from server to browser through HttpClient TransferState (24 items in ng-state, about 8.7 KB), so hydration does not refetch, and `inFlightLoad` de-duplicates the constructor load against the deep-link race.
- [tracker-gallery] Vehicle popups escape all feed strings (`escapeHtml` in vehicle-popup-content.ts) and the JSON highlighter escapes before wrapping spans, so `[innerHTML]` on untrusted upstream feed data is safe; external links use `rel="noopener noreferrer"`, and the proxy allow-lists its upstream host.
- [tracker-gallery] RtSource has a clean, self-rescheduling design with bounded exponential backoff (5 s to 5 min), a visible error state with Try now, and a draft, Apply, Undo model that avoids hammering feeds on every checkbox click; config-driven layer catalogs make a new feed a data-only change.
- [tracker-gallery] The tracker route is lazy with `data: { preload: "hover" }`, the heavy shell is client-rendered on purpose, and signals are scoped carefully (CountdownRingComponent reads the ticking signals itself, the info panel freezes a snapshot so tables do not shift while being read).
- [tracker-gallery] The gallery uses the paginated Relay `medias` connection rather than loading everything, the layout maths lives in a pure, unit-tested util, and the route matcher keeps one component instance across /gallery and /gallery/:id so open and close do not discard the loaded feed.
- [profile-about-misc] The profile page's load() uses a sequence counter (_loadSeq) so a slow response for a previous profile or session can never overwrite the current one, and the dependencies are read outside untracked() so id and auth changes reload correctly; this is covered by specs for id changes, stale responses and retry.
- [profile-about-misc] The methodology registry design (code-first sections and metrics, {{TOKEN}} interpolation that throws on unknown tokens, drift specs that pin constants against the widgets that use them) is a strong pattern for keeping tooltips and the full method consistent; it only needs the page to render what it already holds.
- [profile-about-misc] About page content is rendered through plain interpolation (no innerHTML), href bindings go through Angular's URL sanitiser, outbound links carry rel=noopener noreferrer and an sr-only 'opens in new tab' cue, section jump links respect prefers-reduced-motion and move focus, and the admin editor is lazy-loaded with @defer, with pure, well-specified sanitize/draft utilities.
- [profile-about-misc] My Links keeps its tree and ordering rules in pure, spec-covered utilities (my-links-tree.util, my-links-reasons.util) with bounded, cycle-safe walks, and the 404 page sets a real HTTP 404 through RESPONSE_INIT and picks its joke from a URL hash so server and client renders agree.
- [core-shell] graphqlResource is a careful wrapper: it retains object identity for deep-equal refreshes (cheap keep-alive revalidation), separates isLoading (skeleton gate) from isFetching (in flight), and ties the retry timer to DestroyRef; the initial JS payload is only 88 KB transferred and the 326 KB Sentry replay bundle is correctly kept out of the critical path via addIntegration after bootstrap.
- [core-shell] PollingSource is a model polling primitive: platform-guarded, paused on visibilitychange, wall-clock deadline preserved so a returning tab refreshes immediately only if due, with a resume() that avoids a documented dead-beat trap and a thorough spec file.
- [core-shell] The routing layer is thoughtfully bounded and tested: ReusableRouteStrategy caps detached trees at 10 and destroys evicted handles, RouteScrollMemoryService caps remembered positions at 50 and defers to browser popstate positions, pathWithOptionalParamMatcher keeps one component instance across /gallery and /gallery/:id, and revalidateOnReturn gives keep-alive pages explicit freshness.
- [core-shell] SSR and hydration basics are done right: every browser API is behind injectIsBrowser, PreferencesService hydrates storage in afterNextRender so first paint matches the server, event replay is active (jsaction attributes are in the SSR markup), the theme is applied before paint from an inline script, and the HTTP transfer cache is configured for GraphQL POSTs.
- [core-shell] Stale-deploy resilience is unusually complete: a /version.json poll plus two stale-chunk listeners plus ErrorHandler routing, with pure, unit-tested helpers (isChunkLoadError, isSameCommit), a deliberate no-auto-reload rule that protects in-progress forms, and a logout confirm that guards misclicks.
- [ui-system] The pre-paint theme script in index.html plus oklch light/dark token pairs keyed off a single .dark class and color-scheme gives flash-free dark mode on SSR pages, and the @theme inline brand token auto-follows the .dark override.
- [ui-system] InfoPopover is a careful widget: a root-provided one-at-a-time registry (SSR and TestBed safe), measured viewport clamping and flip-above, hover capability detection with a tap fallback, Escape with focus return, and a well-covered spec.
- [ui-system] AdSlotComponent renders zero ad DOM on the server, reserves an exact fixed height for CLS, only pushes on first intersection, and collapses on unfilled, with pure helpers (mapAdStatus, isAdPreviewEnabled) that are unit-tested.
- [ui-system] HlmButton/HlmBadge follow the Spartan cva + hlm() (clsx + tailwind-merge) pattern with signal input() and host metadata rather than @HostListener, and HlmCheckbox forwards aria-label to the inner button with the reasoning documented.

- [platform] src/server-cache-control.ts is a tiny, pure, well-specified helper (src/server-cache-control.spec.ts covers method, path, status and existing-header cases), and the 20 s s-maxage plus 60 s stale-while-revalidate policy on / is a sensible fit for a live status board.
