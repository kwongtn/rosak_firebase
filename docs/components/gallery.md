# Component: gallery

## 📌 Purpose & Scope

- **Core Responsibility:** The public, read-only `/gallery` page. It shows a chronological, year-grouped, newest-first feed of community spotting photos (`Media` records), with a "jump to year" slider and a full-screen viewer opened by a `:mediaId` route param. The viewer steps to the neighbouring photos (arrow keys, swipe, buttons) and shares a photo's link. Pages load on demand through the backend's Relay-style `medias` connection. The connection is used instead of `mediasGroupByPeriod` for the photos themselves: that field has no pagination argument, so selecting its `medias` sub-field returns every row of each bucket in one call. A shared `/gallery/:mediaId` link does not page through that connection: it fetches the one photo with the backend's `media(id)` query and opens it at once, on the server too, so the server HTML of the link already holds the viewer and the photo's share tags.
- **Domain/Layer:** Angular Presentation (standalone, lazy-routed page, three presentational children, pure utilities). No backend code lives here. It consumes an existing GraphQL API read-only.

## 🔌 Interface & Data Flow

**`GalleryPage`** (`gallery.page.ts`, `app-gallery`). Route: `pathWithOptionalParamMatcher("gallery", "mediaId")` in `app.routes.ts`. `/gallery` and `/gallery/:mediaId` are one route and one component instance, so opening or closing a photo does not destroy the page or its loaded feed.

- **Input:** `mediaIdParam = input<string | undefined>(undefined, { alias: "mediaId" })`. `undefined` means the viewer is closed. A value opens that media: from the loaded feed when it is already there, otherwise by fetching it by id.
- **Output:** none (routed page). Navigates with `Router.navigate(["/gallery", id])` / `["/gallery"]` to keep the URL in sync. Stepping between photos in the viewer passes `{ replaceUrl: true }`, so Back returns to the grid instead of walking back through every photo seen.
- **Computed:** `yearGroups: YearGroup[]` (`{ year, items: MediaNode[] }[]`, derived from loaded `edges`). `yearCounts` is sorted descending, from the separate year-count aggregate. That aggregate is requested in the browser only (see `MEDIA_YEAR_COUNTS_QUERY` below), so it is empty in the server HTML. `prevMedia` / `nextMedia` are the loaded photos either side of the open one (`MediaNode | null`, found by id in the flat `edges()` list, so across year groups; both `null` for a photo the feed has not reached, and `nextMedia` is `null` at the end of what is loaded). `sharePath` is the open photo's own route, built by the router (`serializeUrl(createUrlTree(["/gallery", id]))`), the very path the address bar shows.

`TARGET_ROW_HEIGHT = 220` is exported from `JustifiedGridComponent`, which scales every tile's `flex-basis` by it, and reused by `gallery.page.ts` to size loading skeletons. `GalleryPage` passes `eagerCount = 4` (`EAGER_IMAGE_COUNT`) to the first year's grid only.

**GraphQL** (`data/gallery.queries.ts`; read-only, no mutations):

- `MEDIAS_QUERY` (`MediasFeed`): `medias(first, after, order: { created: DESC })` → `{ totalCount, pageInfo { hasNextPage, endCursor }, edges [{ cursor, node: MediaNode }] }`. `MediaNode = { id, createdDate, width, height, file: { url } | null, uploader: { nickname } | null }`. `uploader` is null for a photo attached to an anonymous spotting, for every viewer except the uploader and admins: the photo still shows, with no name (the label is "Photo, {date}" and the viewer drops its "Uploaded by" row).
  Backend note: the `medias` order was not total until `rosak_backend` `7a02ef4`. `MediaOrder` offered `created` and `modified` only and the resolver added no tie-break, so rows that tied were returned in no fixed order and the positional (`arrayconnection:N`) cursors paged unreliably: a page could repeat a row of the page before it, and a row could be skipped. On the dev data a walk of the whole feed 24 rows at a time fetched 2,439 rows of which 2,438 were distinct (the repeat started page 2), so one photo was never reached. The backend now appends the primary key as the last sort key of every `medias` order and sorts a feed with no `order` argument by it. `GalleryPage.loadMore()` still keeps the first sighting of a photo and drops a repeat (see Pagination model), which is now a guard. It could never bring back a photo that the old order skipped.
- `MEDIA_BY_ID_QUERY` (`MediaById`): `media(id: ID!)` → `MediaNode | null`, the same selection as one feed node. `id` is the Relay global id the feed exposes, passed verbatim (a raw database id returns `null`); `null` means there is no such photo. Legacy rows whose `file` is empty (417 of 2,856 in the dev data) are hidden by the backend (`MediaType.get_queryset`): `media(id)` returns `null` for one, and no feed page errors on one (the feed lists 2,439 photos, as many as `mediasGroupByPeriod` counts). The page treats `null` as it does any missing photo. `rosak_backend/docs/components/common.md` (Known defect 5) tracks it.
- `MEDIA_YEAR_COUNTS_QUERY` (`MediaYearCounts`): metadata-only `mediasGroupByPeriod(type: YEAR) { year count }`, a GROUP BY aggregate kept off the SSR path. `GalleryPage` requests it in the browser only (its `graphqlResource()` request function returns `undefined` on the server), because SSR holds the response until an `httpResource` settles and the counts feed nothing but the year slider. The slider fills in after hydration and reserves its height meanwhile (`GalleryYearSliderComponent` is `invisible` with a `min-height` while empty). It never loads images and never sub-selects `medias`.

**Dependencies:**

- `GraphQLClient.request()` (`core/graphql/graphql-client.ts`): one-shot calls, the paginated `medias` pages and the single `media(id)` fetch. The page drives its own accumulation, so the calls are not resource-bound. It is `HttpClient` underneath, so SSR waits for them and hydration reuses the transferred responses.
- `graphqlResource()` (same file): `httpResource` wrapper with exponential-backoff retry. Used only for `MEDIA_YEAR_COUNTS_QUERY`, and only in the browser.
- `ToastService` (`ui/toast/toast.service.ts`, wraps `@spartan-ng/brain/sonner`): load-failure, "still loading" and "not found" feedback, and the viewer's "Link copied" confirmation. The viewer also injects `ErrorHandler` (a share that fails for any reason but the visitor dismissing the sheet).
- `HlmButton` (the "Load more" button), `HlmSkeleton` (initial-load rows), `AppNavComponent` / `AppFooterComponent` (`shell/`).
- `Router` (URL sync for the open media). Angular's `DatePipe` (viewer date) and `formatDate` (`mediaLabel`).
- `Title` and `Meta` (`@angular/platform-browser`): the open photo's document title and share tags.
- `CdkTrapFocus` (`@angular/cdk/a11y`): the viewer's focus trap, the same primitive `HlmSheet` uses.
- `injectIsBrowser()` (`core/composables/is-browser.ts`) gates browser-only work: the year-count request, DOM scroll, and the `document.body` scroll lock.
- Pure, framework-agnostic utilities, each independently unit-testable: `data/imgur.util.ts` (`getImgurThumbnail`, the Imgur URL-suffix thumbnail trick) and `data/media-label.util.ts` (`mediaLabel`, the photo's accessible name).

## ⚙️ Internal State & Logic

- **`GalleryPage`** holds all feed state in signals: `edges` (accumulated `MediaNode` edges across loaded pages), `hasMore`, `isLoading`, `isJumping`, `jumpTargetYear`, `selectedMedia`. `yearGroups` and `_loadedYears` are `computed()` from `edges`.
- **Concurrency:** a single `inFlightLoad: Promise<boolean>` field (a plain field, not a signal) de-duplicates concurrent `loadMore(pageSize = PAGE_SIZE)` calls, where `PAGE_SIZE = 24`. The constructor's initial load and a year jump clicked before it lands can race. `loadMore()` returns whether the load succeeded, so loops can stop instead of hammering a failing request.
- **Pagination model:** `edges` only ever grows (append-only cursor accumulation), and holds each photo once. `loadMore()` asks for the page after the cursor of the last row the backend sent (`endCursor`, a plain field, set from every response) and appends only the photos `edges` does not hold yet, as a guard against the repeats described above. `endCursor` is kept apart from `edges` on purpose: a page that is nothing but repeats adds nothing, and asking again from the last photo kept would bring the same page back for good. There is no server-side year filter. `jumpToYear()` goes through the `loadUntil()` loop. It pages forward at `JUMP_PAGE_SIZE = 100`, throttled by `JUMP_REQUEST_DELAY_MS = 200`, and capped at `MAX_JUMP_PAGES = 100`, until the target year appears or the feed is exhausted. While it runs (`isJumping()`), a "Loading {year}…" pill (spinner and text, `data-testid="gallery-jump-loading"`) shows fixed at the bottom of the viewport, inside an always-present `role="status"` region so the text is announced, and the year buttons are disabled. Opening a photo by id never pages.
- **URL ↔ state sync:** an `effect()` in the constructor watches `mediaIdParam` and opens or closes `selectedMedia` to match. `openMediaById()` opens a photo the feed already holds (Back/Forward) without a request. Otherwise it fetches that one photo with `MEDIA_BY_ID_QUERY` and opens the viewer when it arrives, on the server too: the server HTML of `/gallery/:mediaId` carries the viewer, and the browser's hydration reuses the transferred response. The feed (`loadMore()`) loads independently. A `null` photo shows the "Couldn't find that photo" toast and then `navigate(["/gallery"], { replaceUrl: true })`, which is a redirect to `/gallery` when it happens on the server. A thrown request (5xx, timeout, GraphQL error) is not "no such photo": in the browser it shows the "Couldn't load that photo" toast (none for a `GraphQLRequestError`, which `GraphQLClient` has already toasted) and navigates the same way; on the server it renders the gallery without the viewer, does not navigate, and reports the error through `ErrorHandler` (Sentry), because `GraphQLClient` only reports in the browser. After a 5xx or timeout the shared link survives: the browser asks again on hydration. A GraphQL `errors` answer is an HTTP 200, so the transfer cache replays it and the browser then fails the same way: the `GraphQLClient` toast, then a fall back to `/gallery`. A non-GraphQL failure in the browser (offline, 5xx) toasts "Check your connection and try again.". An answer that arrives after the route has moved on is dropped. UI-driven open and close set the signal directly, for instant feedback, then navigate separately. The effect's own already-open check turns the resulting route callback into a no-op.
- **Share metadata:** while a photo is open, an effect on `selectedMedia` sets the document title (`MLPTF | Photo by {nickname}, {d MMM y}`, the `mediaLabel()` words), `og:title`, `og:description`, `og:image` (the photo at Imgur's `h` size, `getImgurThumbnail(url, "h")`) and `og:image:alt` through `Title` and `Meta`, so the server HTML of a shared link previews as that photo. A photo without a file keeps the site-wide `og:image`. The effect's cleanup restores the defaults when the viewer closes, the photo changes or the page is left: the title to `MLPTF | Gallery` (the route title), `og:image` to the site-wide share card (`https://community.mlptf.org.my/share-card.png`, also set statically in `src/index.html`), `og:image:alt` to the site-wide text (the same as in `index.html`), and the `og:title` and `og:description` tags are removed (`index.html` has none). `index.html` sets no `og:image:width`/`og:image:height` (they would be wrong for a shared photo) and already carries `twitter:card`, so neither is written here. The effect also reads `mediaIdParam` so that it re-runs once a click-opened photo's navigation has landed: the router resets the title to the route's on every `NavigationEnd`.
- **Viewer navigation:** `MediaViewerComponent` owns no list. `GalleryPage` finds the open photo in `edges()` (`_openIndex`, `-1` when it is not there) and passes the photos either side of it as `prev` / `next`. When the viewer emits `navigate`, `onStepMedia()` does what opening does: it sets `selectedMedia` at once, for instant feedback, then navigates with `replaceUrl: true`. The neighbour lookup (`neighbourOf()`) is the entry either side of the open photo in `edges()`, which holds each photo once. The share-metadata effect follows `selectedMedia`, so the title and share tags change with each step, and the `mediaIdParam` read in it re-applies them after the router resets the title on `NavigationEnd`. When the open photo is the last one loaded and `hasMore()` (`_atFeedEnd`), an effect calls `loadMore()`, so Next does not hit a wall while the feed has more. It is a browser-only effect, and it reads a boolean: a page that fails or comes back empty leaves that boolean as it was, so it cannot retry in a loop. The next photo the visitor opens at the end tries once more (stepping off the last photo and back counts: the boolean flips), and the "Load more" button and a year jump still work as before (`loadMore()` is de-duplicated). A page that is nothing but repeats leaves Next waiting in the same way, and that retry starts from where the page ended.
- **`JustifiedGridComponent`** is stateless and measures nothing, so the server renders exactly what the browser does and the first page of photos is in the SSR HTML. One `flex flex-wrap` container (6 px gap); each tile's `flex-basis` is `aspect × TARGET_ROW_HEIGHT` px and its `flex-grow` is `aspect × 100`, so the browser fits as many tiles per row as the width allows and stretches the row to the full width at one shared height. A tile is a `div` holding a `padding-bottom: 100 / aspect %` box (it reserves the tile's height before the image arrives) and an absolutely positioned button with the `object-cover` image. A trailing spacer with `flex-grow: 1000000` keeps the last, incomplete row at the target height. `aspect` is `width / height`, or 4:3 when either is missing. The first `eagerCount` images use `loading="eager"` (the very first also `fetchpriority="high"`) and the rest `loading="lazy"`.
- **`MediaViewerComponent`** has no state beyond its inputs, the start of a swipe in progress and whether the page is pinch-zoomed (`zoomed`, a signal). It sets `document.body.style.overflow` (a scroll lock) in its constructor and clears it in `ngOnDestroy`. It listens for Escape with `(document:keydown.escape)`, and for ArrowLeft / ArrowRight with `(document:keydown.arrowleft|arrowright)`, which Angular matches only without a modifier, so Alt+Left (the browser's Back) is left alone. `step(target)` emits `navigate` with the neighbour and does nothing for `null`. A swipe is a `pointerdown` / `pointerup` pair on the photo area: a lone primary touch or pen pointer (a mouse is ignored; a second finger or a `pointercancel` calls it off) that travels at least `SWIPE_MIN_PX = 50` px sideways, and further sideways than up or down. Left goes to `next`, right to `prev`. The photo area is `touch-pan-y touch-pinch-zoom`, so the browser keeps vertical scroll and pinch zoom and does not cancel a sideways drag. While the page is pinch-zoomed (`visualViewport.scale` above `ZOOMED_SCALE = 1.01`, followed through the `resize` event `visualViewport` fires, and read once on open) no swipe starts and the area adds `touch-pan-x`: spotters zoom in to read a vehicle number, and a sideways drag must then pan the photo, which `touch-pan-y` alone would forbid. A browser without `visualViewport` never counts as zoomed. Previous / Next buttons (`aria-label="Previous photo"` / `"Next photo"`, the non-gesture way to do the same) show whenever either neighbour exists. At an end the button stays and is `aria-disabled` rather than `disabled`: a disabled button that has focus drops it, and that would let focus out of the trap. With a `sharePath` a Share button shows in the header, on the server too so hydration finds the same DOM. `share()` runs from the click. On a touch device (a coarse primary pointer, `(pointer: coarse)`: a phone or tablet) whose browser has `navigator.share` it calls `navigator.share({ url, title })` (`url` is `location.origin` plus the path, `title` is the photo's `mediaLabel()`), and a dismissed sheet (`AbortError`) ends there. Any other share failure goes to `ErrorHandler` and the link is copied instead, as it is on every other device, desktop browsers with a share dialog included (it is a clunky way to pass a link on there), and in a browser with no `matchMedia`; a touch laptop whose primary pointer is its trackpad also copies: `navigator.clipboard.writeText(url)` and a "Link copied" toast, or a "Couldn't copy link" toast when the clipboard refuses or does not exist (an insecure page). The clicks on Share and on Close do not bubble: the host closes the viewer on any click that reaches it, which would make Close emit `close` twice. It is a modal dialog: the host has `role="dialog"`, `aria-modal="true"` and `aria-label="Photo viewer"`, and a `cdkTrapFocus` wrapper with auto-capture moves focus to the Close button on open (`cdkFocusInitial`, since Share comes before it in the DOM), keeps Tab inside, and restores focus to the element that had it before (the thumbnail that opened it) when the viewer is destroyed. The image `alt` is `mediaLabel(media)`.
- **`GalleryYearSliderComponent`** is stateless: inputs in, template out.
- **Names and motion:** each thumbnail button gets `aria-label="Photo by {nickname}, {d MMM y}"` from `mediaLabel()`, which drops whichever part is blank (many photos have no nickname, a photo on an anonymous spotting has no uploader for most viewers, and incident photos have no date). The thumbnail `<img>` stays `alt=""`. `jumpToYear()` scrolls (in `afterNextRender`, once the target year's section is in the DOM, and only if the page has not been destroyed meanwhile, since a long jump can outlive a navigation away) with `behavior: "auto"` when `prefers-reduced-motion: reduce` matches, and `"smooth"` otherwise. `yearGroups` takes each photo's year from the first four characters of `createdDate` (`YYYY-MM-DD`), not a `Date` parse, so it matches the formatted labels.

## 🧩 Extension Points & Hooks

- **`JustifiedGridComponent` and `MediaViewerComponent`** are input/output driven and reusable for any `MediaNode[]` or `MediaNode`, without touching `GalleryPage`. The viewer's `prev` / `next` / `sharePath` are all optional: the insiden incident card passes only `media` and `close`, and gets the plain viewer, with no arrows and no Share button (an incident photo has no `/gallery/:mediaId` page to share). A host that has a list wires `navigate` to whatever selects a photo, as `GalleryPage.onStepMedia` does.
- **`getImgurThumbnail()`** is generic and has no Angular or gallery coupling.
- **`graphqlResource()`** is a shared primitive (auto-retry, SSR TransferState). The gallery uses only `data`, with no manual `retryNow()`, and requests it in the browser only.
- **`pathWithOptionalParamMatcher`** (`core/routing/optional-param-matcher.ts`) is the reusable convention that keeps `/gallery` and `/gallery/:mediaId` as one component instance. `/insiden` uses it too (`date` param).
- No `ng-content` slots, decorators or interceptors. Extension is by composition (new child components and inputs).

## 💡 Potential Feature Opportunities

- **Tell screen-reader users the photo changed, and preload the neighbours.** Stepping leaves focus on the pressed button and changes only the image and its `alt`, which a screen reader does not announce; consecutive photos from one uploader on one day even share their label. An `aria-live` line needs the photo's position ("3 of 24"), which the host would pass down. Preloading the `prev` / `next` images (`new Image()`) would make a step instant; it costs mobile data for photos that may never be opened.
- **Infinite scroll instead of "Load more".** Still a button in `gallery.page.html`. `hasMore`, `isLoading` and the de-duplicated `loadMore()` are already in place. Ready: place the shared sentinel directive `appInfiniteScroll` (`ui/infinite-scroll/`; emits `loadMore`, takes `appInfiniteScrollLoading`) below the grid. Insiden's incident card uses the same pattern.
- **Filter the feed by uploader.** `MediaNode.uploader?.nickname` is fetched on every edge (null for photos on anonymous spottings), so client-side filtering of loaded pages is possible now. Server-side filtering is not: the `medias` connection has no filter argument. A `uploader` / `MediaFilter` argument on the Strawberry `medias` resolver in `rosak_backend` has to come first.
- **Bulk-download a year's photos.** Each `MediaNode` carries `file.url`, so a per-year download action is largely client-side. Nothing in the app orchestrates multi-file downloads or zipping, and it needs a small utility: fetch-and-zip in the browser, or a backend batch export if large galleries make client-side zipping impractical. COMPONENTS.md lists the shared export utility.

## 💡 Potential AI Feature Opportunities

- **Auto-generated alt text.** Photos are named only by who uploaded them and when (`mediaLabel()`); nothing describes what they show. An image-captioning model at ingestion could fill meaningful alt text and searchable metadata, which would also make the feed searchable.
- **Semantic search.** The year slider offers only coarse year-bucket navigation over `created`-ordered results, with no server-side filter. A vector index over photo content or uploader/date metadata could support natural-language or visual-similarity search without waiting on the `MediaFilter` argument.
- **Content moderation and duplicate detection.** Ingestion is bot-driven (Discord/Telegram) with no human upload gate, and this page is public and unauthenticated. An AI pass (NSFW, spam, duplicate-image detection) could run before photos reach it.
