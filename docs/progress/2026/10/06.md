## Round 2g (refinement)

Home-page polish, round 2 continued — the plan is `.omo/plans/home-page-polish-round2.md` ("Round 2g"), findings in `.omo/notepads/home-page-polish/round2g.md`. Frontend-only: CSS and one spec, no new read, no backend change, no new dependency.

**home** — the "Updating" spinner's draw-in entrance, narrowed to the bright line.

**The ask:** the faded background circle should be **always there** (static, visible from the first
frame), and the bright line should **start at 3 o'clock and draw anticlockwise** before the delayed
spin takes over.

**What changed** (`home-refresh-control.component.ts` + spec, `src/styles.css`):

1. **The backdrop circle is STATIC.** The track `<circle>` (r 9, `stroke-opacity="0.25"`) lost its
   `stroke-dasharray="56.55"`, its `animate-spinner-draw-ring` and its `motion-reduce:animate-none` —
   it is plain markup at the default `stroke-dashoffset: 0`. It is the surface the line draws onto, so
   it is there from the first frame; animating it too meant the glyph's own backdrop was still
   arriving 500ms after the "Updating" state did.
2. **Only the line animates in.** The arc `<path>` is unchanged: `stroke-dasharray="14.14"` +
   `animate-spinner-draw-arc motion-reduce:animate-none`, then the svg's
   `[animation:spin_1s_linear_500ms_infinite_reverse]` takes over — the 500ms delay is what waits for
   the draw.
3. **"From 3 o'clock anticlockwise" is the path's own geometry, not extra direction.** `M20 11` IS 3
   o'clock and sweep flag `0` walks negative-angle (anticlockwise in SVG's y-down frame) to `(2,11)`,
   12 o'clock, so decreasing `stroke-dashoffset` from the path's own length to 0 reveals the stroke
   forward from the path's start — that same quarter turn. The template comment now argues this out,
   so nobody "fixes" the direction by reversing the path and desyncing the draw from the geometry.
4. **The dead token is deleted.** `--animate-spinner-draw-ring` and its `@keyframes spinner-draw-ring`
   are removed from `src/styles.css`; `--animate-spinner-draw-arc` stays (still a **global** `@theme`
   token — the emulated-encapsulation trap in `MISTAKES.md` is unchanged).
5. **Spec** (the entrance test became "draws ONLY the bright line IN … over a static faded backdrop"):
   the track asserts `stroke-opacity="0.25"`, a **null** `stroke-dasharray` and a **null** `class`;
   the arc keeps its draw class, `"14.14"` and reduced-motion opt-out; the no-inline-animation /
   no-`style`-attribute guard now walks svg + arc instead of track + arc.

**Evidence:** live in the browser — the track reads `animation-name: none`, `stroke-dashoffset: 0px`
and no dasharray at every sampled frame (it never moves), while the arc's offset walks
**14.14 → 13.36 → 11.87 → 9.78 → 7.24** over the first frames of the 500ms draw, before the delayed
rotation begins. As in 2f, jsdom computes no styles, so the spec pins the class/dasharray strings and
a human confirms the computed animation.

  spinner bullet, and the `line-refresh-ring` testid entry), this entry, one SUMMARY row and
  `.omo/notepads/home-page-polish/round2g.md`.

## Round 2h (refinement)

Home-page polish, round 2 continued — the plan is `.omo/plans/home-page-polish-round2.md` ("Round 2h"), findings in `.omo/notepads/home-page-polish/round2g.md`. Frontend-only: one component + its spec, CSS and `src/styles.css` untouched, no backend change.

**home** — the "Updating" spinner's entrance no longer waits for its own draw-in.

**The ask:** "spin as it is appearing" — the rotation should run WHILE the bright line draws in, not only afterwards. Round 2g's entrance was two sequential phases (a still circle for 500ms, then a spin), which reads as a pause rather than as one motion.

**The change** (`home-refresh-control.component.ts` + spec), one token:

- `[animation:spin_1s_linear_500ms_infinite_reverse]` → `[animation:spin_1s_linear_infinite_reverse]`.
  The **500ms delay is gone**, so the glyph is already rotating from the first frame and the spin and
  the arc's 500ms draw share the whole window: the line draws from 3 o'clock anticlockwise _on a
  rotating glyph_. Duration is still 1s, `reverse` still rides **inside** the shorthand (the
  notepad trap stands — the shorthand resets every sub-property), and the draw
  (`animate-spinner-draw-arc`) and the static faded track are byte-for-byte unchanged.
- Template comment: the entrance passage now says the rotation runs WHILE the line draws in (both
  animations start together); the "only THEN does the rotation start" / delayed-take-over phrasing is
  gone, and the 3-o'clock-anticlockwise passage names the already-rotating glyph.

**Spec:** the entrance test is renamed "draws ONLY the bright line IN **while the spin is ALREADY
rotating**, over a static faded backdrop"; the svg assertion flips from the delayed shorthand to
`[animation:spin_1s_linear_infinite_reverse]` **plus** a guard that no time slot crept back in ahead of
`infinite` (a delay reappearing as a fourth token is the regression). The arc draw + static-track
assertions stay. The `reads as Updating…` test's shorthand assertion was flipped for the same reason.

**Evidence:** scoped suite `34 passed` (34 tests, 1 file); `prettier --check` clean on both files. As in
2f/2g, jsdom computes no styles — the spec pins the shorthand string and the delay guard; whether the
spin is visibly concurrent with the draw is the one thing a browser look confirms.

## Round 2i (refinement)

Home-page polish, round 2 continued — the plan is `.omo/plans/home-page-polish-round2.md` ("Round 2i"), findings in `.omo/notepads/home-page-polish/round2g.md`. Frontend-only: one component + its spec; `src/styles.css`, the draw keyframe and the arc geometry untouched, no backend change.

**home** — the "Updating" spinner's arc starts at 12 o'clock, and the spin is half speed.

**The ask:** the bright line should start at the **12 o'clock** position rather than 3 o'clock, and the spin should be **half** its current speed.

**The two changes** (`home-refresh-control.component.ts` + spec):

1. **Both strokes moved into `<g transform="rotate(-90 11 11)">`** — a quarter turn anticlockwise about the ring's own centre, which moves the visible geometry (and therefore the draw-in's start) to 12 o'clock. The draw is still **anticlockwise**; only its start point moved. The track, the arc's `animate-spinner-draw-arc` and its `stroke-dasharray="14.14"` are byte-for-byte unchanged.
   🔴 **It is a group transform, not a `-rotate-90` class on the svg.** The spin animation writes `transform` on the svg itself, so a class there is overwritten on the first frame and the start point snaps back to 3 o'clock mid-spin; a **group** transform composes with the parent's animation instead. The path itself is untouched — `M20 11a9 9 0 0 0-9-9` still starts at 3 o'clock in its own coordinates and still sweeps anticlockwise; reversing it would only desync the draw from the geometry.
2. **Spin halved**: `[animation:spin_1s_linear_infinite_reverse]` → `[animation:spin_2s_linear_infinite_reverse]`, `reverse` still **inside** the shorthand (it resets every sub-property, so a separate `animation-direction` stays dead markup) and still **no delay**. At 1s the glyph read as a spinner rushing; nothing else on the page moves that fast.

**Spec:** both shorthand assertions flip to `spin_2s_linear_infinite_reverse`, and the entrance test's regex guard against a delay token is unchanged (it rejects any `\d+m?s` in front of `infinite`). Two new assertions: the `<g transform="rotate(-90 11 11)">` wrapper exists, holds **both** strokes (2 children), and the svg carries **no** `-rotate-90` class — the regression this change exists to prevent.

**Evidence:** scoped suite `34 passed` (34 tests, 1 file); `npx prettier --check` clean on both files. As in 2f/2g/2h, jsdom computes no styles and cannot see a rotation — whether the line visibly begins at 12 o'clock is the one thing a browser look confirms.

- **Docs**: `docs/components/home.md` (the refresh-control seam passage, the Internal-State spinner paragraph, and the Motion "Updating" spinner bullet — the 3-o'clock rule rewritten as the 12-o'clock group-transform rule), this entry, one SUMMARY row, `.omo/plans/home-page-polish-round2.md` and `.omo/notepads/home-page-polish/round2g.md`.

Plan and per-task findings in `.omo/notepads/home-page-round3/learnings.md`. Frontend-only: no GraphQL

### home/line-pulse: the board says what it is doing

1. **The pinned line looks pinned.** The kebab's pin item fills its glyph
   (`[class]="_isPinned() ? '[&>svg]:fill-current' : ''"` merged with the static `class="size-4"`), so a
   pinned line's pin is a solid shape rather than an outline the reader has to remember.
2. **"Details" is a button, and it sits LEFT of "Report status".** `line-pulse-card.component.ts` gains a
   real `<a hlmBtn size="sm" variant="outline" [routerLink]="['/spotting', line().id, 'details']
data-testid="line-card-details">` as the FIRST child of the existing action cluster — `hlmBtn`'s
   selector already accepts `a[hlmBtn]`, so no extra wiring, and `hlm()` merges `w-full sm:w-auto` into
   the cluster's `flex-col`-on-mobile stacking unchanged. `lucideExternalLink` left the import.
3. **"Line HQ" is gone everywhere** — an explicit user decision, not a de-duplication: the card kebab's
   two `line-card-hq*` items, the row's `line-row-hq` pro block, and the Pro dashboard's
   `ProLineHqWidgetComponent` (component + spec **deleted**; the bento's row C keeps its grid classes and
   its remaining cells keep the "six cells" / "three supporting surfaces" counts in the class doc and
   template comments). `/spotting/:lineId/details` stays — it is what "Details" points at, now visible
   instead of buried.
4. **The collapsed row's 24-cell history strip is replaced by `N reports (X this hour)`.**
   `line-history-strip.component.ts` is **deleted** (its tests lived inside the row spec, so they were
   rewritten, not moved), and `line-pulse-row.component.ts` now injects `HomeStore`, calls
   `requestHistoryReads()` itself and reads `linesHistoryFor(line().id)`. N is `historyTotal(buckets)`
   over the service day; X comes from the new pure `currentServiceBucketIndex(buckets, now)` in
   `data/status-history-display.util.ts` (half-open `[start, end)`, so a seam instant belongs to the
   LATER hour). The label is wrapped in `app-info-popover` (`line-row-reports-popover`) reading the new
   **`network.line-reports-summary`** methodology doc ("A line's reports today"), with
   `REVIEWED_AT_HISTORY_WIDGETS` bumped to `"2026-10-06"`; the `buckets: []` fallback deliberately
   stays a bare `<span>` because "reported nothing today" is not an error, and a service-day definition
   would not describe a 15-minute rolling count. 🔴 **SSR is the load-bearing detail**: `_now` is seeded in
   `afterNextRender` only and the `refreshTick` effect must not write the clock on its first run (an
   `effect` runs during change detection, i.e. before `afterNextRender`), or a client-clock string lands
   in the first paint the server never produced — NG0500.
5. **Board groups are separated by dividers.** The two lower sections (`line-board-mine`,
   `line-board-all`) carry `border-border … border-t pt-4`; the attention group is untouched because the
   controls row's own bottom border already sits above it, and the user asked for separation only, no
   regrouping.
6. **Comfortable/Compact density is removed end-to-end**, in three legs that each had to land for the
   next: the board's density control group, the dead `BOARD_DENSITIES` const, `_densityOptions`,
   `_density`, `setDensity()` and both `[density]` bindings (the board's only use of
   `PreferencesService`, so the injection went too); the `density` input on `LinePulseRowComponent`
   (padding hardcoded `p-3 pl-4`); and the preference itself in `PreferencesService`
   (`PreferencesDensity`, `DENSITIES`, the field in `Preferences` / `DEFAULT_PREFERENCES` / `defaults()` /
   `parseStoredPreferences` / `snapshot()` / `reset()`, the `_density` signal, `density` and
   `setDensity()`). The storage key stays `rosak:preferences:v1` and **nothing migrates** —
   `parseStoredPreferences` reads named keys off the record, so a stale `density` key in a rider's
   payload is simply never looked at. That is why the field was dropped from parsing rather than
   defaulted.

### home/pro heat grid: the grid becomes readable

`network-heat-strip.component.ts`, five changes:

1. **Full line codes** — the gutter widens `w-12` → `w-20`, `truncate` is dropped and
   `[title]="row.displayName"` is added, so a truncated code never hides which line it is. The `w-20`
   had to be repeated in THREE places (the "Service day …" spacer, the new tick row's spacer, the row)
   or the axis describes columns that sit nowhere.
2. **An alternating hour axis.** `_axis()` labels every other column (`index % 2 === 0`) — 12 labels for 24
   columns, because all 24 collide at this cell width.
3. **Lines with no buckets draw 24 grey cells** (`data-empty`) instead of a blank strip. `_columns()` is
   the **first visible line with `buckets.length > 0`**, and each row looks its own hour up in a
   per-row `Map<hourStart, bucket>`, so the grid keeps a stable 24 columns whatever the backend returned.
   `_hasCells` had to move to `_columns().length > 0` — the old
   `rows.some(row => row.cells.length > 0)` would be true for those grey-only rows.
4. **A hover breakdown popover** (profile-style) replaces the per-cell `title`: ONE panel inside a
   `relative` `heat-grid` wrapper (never inside a cell), cleared on that wrapper's `mouseleave`.
   Position is **measured**, not guessed — `onCellEnter` reads the cell's and the wrapper's
   `getBoundingClientRect()`, then an effect reads the panel's own `offsetWidth/offsetHeight` and writes
   a `left`/`top` clamped to the wrapper; the panel stays `visibility: hidden` until that pass lands and
   `_panelPos` resets to `null` on every hover, so the previous cell's coordinates cannot flash.
   `ROWS_POPPING_BELOW = 2`: above-ness is the row INDEX, not measured space — the first row sits ~20px
   under the axis.
5. **The current-hour glow is SSR-safe.** `_now` is seeded in `afterNextRender` and refreshed by an
   effect on `store.linesRefreshTick()` gated by a `_clockSeeded` flag (the row's exact pattern). The
   marker is a `pointer-events-none absolute -inset-px ring-2 ring-amber-400/80 … motion-safe:animate-pulse`
   **span inside** the cell, never a class on it — `animate-pulse` on the cell would fade the status
   colour that carries the data.

`heatCellTitle` is deleted from `status-history-display.util.ts` (the chart/sparkline use
`historyBarTitle`, untouched) along with its spec test.
