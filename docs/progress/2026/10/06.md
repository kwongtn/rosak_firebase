## Round 2g (refinement)

Home-page polish, round 2 continued — the plan is `.omo/plans/home-page-polish-round2.md` ("Round 2g"), findings in `.omo/notepads/home-page-polish/round2g.md`. Frontend-only: CSS and one spec, no new read, no backend change, no new dependency.

**home** — the "Updating" spinner's draw-in entrance, narrowed to the bright line.

**The ask:** the faded background circle should be **always there** (static, visible from the first
frame), and the bright line should **start at 3 o'clock and draw anticlockwise** before the delayed
spin takes over.

**What changed** (`home-refresh-control.component.ts` + spec, `src/styles.css`):

1. **The backdrop circle is STATIC.** The track `<circle>` (r 9, `stroke-opacity="0.25"`) lost its
   `stroke-dasharray="56.55"`, its `animate-spinner-draw-ring` and its `motion-reduce:animate-none` —
   it is plain markup at the default `stroke-dashoffset: 0`. It is the surface the line draws onto, so
   it is there from the first frame; animating it too meant the glyph's own backdrop was still
   arriving 500ms after the "Updating" state did.
2. **Only the line animates in.** The arc `<path>` is unchanged: `stroke-dasharray="14.14"` +
   `animate-spinner-draw-arc motion-reduce:animate-none`, then the svg's
   `[animation:spin_1s_linear_500ms_infinite_reverse]` takes over — the 500ms delay is what waits for
   the draw.
3. **"From 3 o'clock anticlockwise" is the path's own geometry, not extra direction.** `M20 11` IS 3
   o'clock and sweep flag `0` walks negative-angle (anticlockwise in SVG's y-down frame) to `(2,11)`,
   12 o'clock, so decreasing `stroke-dashoffset` from the path's own length to 0 reveals the stroke
   forward from the path's start — that same quarter turn. The template comment now argues this out,
   so nobody "fixes" the direction by reversing the path and desyncing the draw from the geometry.
4. **The dead token is deleted.** `--animate-spinner-draw-ring` and its `@keyframes spinner-draw-ring`
   are removed from `src/styles.css`; `--animate-spinner-draw-arc` stays (still a **global** `@theme`
   token — the emulated-encapsulation trap in `MISTAKES.md` is unchanged).
5. **Spec** (the entrance test became "draws ONLY the bright line IN … over a static faded backdrop"):
   the track asserts `stroke-opacity="0.25"`, a **null** `stroke-dasharray` and a **null** `class`;
   the arc keeps its draw class, `"14.14"` and reduced-motion opt-out; the no-inline-animation /
   no-`style`-attribute guard now walks svg + arc instead of track + arc.

**Evidence:** live in the browser — the track reads `animation-name: none`, `stroke-dashoffset: 0px`
and no dasharray at every sampled frame (it never moves), while the arc's offset walks
**14.14 → 13.36 → 11.87 → 9.78 → 7.24** over the first frames of the 500ms draw, before the delayed
rotation begins. As in 2f, jsdom computes no styles, so the spec pins the class/dasharray strings and
a human confirms the computed animation.

## Round 2h (refinement)

Home-page polish, round 2 continued — the plan is `.omo/plans/home-page-polish-round2.md` ("Round 2h"), findings in `.omo/notepads/home-page-polish/round2g.md`. Frontend-only: one component + its spec, CSS and `src/styles.css` untouched, no backend change.

**home** — the "Updating" spinner's entrance no longer waits for its own draw-in.

**The ask:** "spin as it is appearing" — the rotation should run WHILE the bright line draws in, not only afterwards. Round 2g's entrance was two sequential phases (a still circle for 500ms, then a spin), which reads as a pause rather than as one motion.

**The change** (`home-refresh-control.component.ts` + spec), one token:

- `[animation:spin_1s_linear_500ms_infinite_reverse]` → `[animation:spin_1s_linear_infinite_reverse]`.
  The **500ms delay is gone**, so the glyph is already rotating from the first frame and the spin and
  the arc's 500ms draw share the whole window: the line draws from 3 o'clock anticlockwise _on a
  rotating glyph_. Duration is still 1s, `reverse` still rides **inside** the shorthand (the
  notepad trap stands — the shorthand resets every sub-property), and the draw
  (`animate-spinner-draw-arc`) and the static faded track are byte-for-byte unchanged.
- Template comment: the entrance passage now says the rotation runs WHILE the line draws in (both
  animations start together); the "only THEN does the rotation start" / delayed-take-over phrasing is
  gone, and the 3-o'clock-anticlockwise passage names the already-rotating glyph.

**Spec:** the entrance test is renamed "draws ONLY the bright line IN **while the spin is ALREADY
rotating**, over a static faded backdrop"; the svg assertion flips from the delayed shorthand to
`[animation:spin_1s_linear_infinite_reverse]` **plus** a guard that no time slot crept back in ahead of
`infinite` (a delay reappearing as a fourth token is the regression). The arc draw + static-track
assertions stay. The `reads as Updating…` test's shorthand assertion was flipped for the same reason.

**Evidence:** scoped suite `34 passed` (34 tests, 1 file); `prettier --check` clean on both files. As in
2f/2g, jsdom computes no styles — the spec pins the shorthand string and the delay guard; whether the
spin is visibly concurrent with the draw is the one thing a browser look confirms.
