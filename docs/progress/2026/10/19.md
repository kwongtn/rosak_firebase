# 2026-10-19

Homepage UX and performance pass. Uncommitted at the time of writing, so no commit refs.

## Home: hero CTA, mobile bar, and shortcuts

- **Hero CTA**: "Report a delay" is the single primary action (filled, `h-11`). "Spot a train" and
  "Share a link" are outline buttons, and "Live map" is link-styled. The `h1` carries `aria-live="polite"`.
- **Mobile action bar**: four 44px controls, Report · Spot a train (icon-only) · Refresh · Live map.
- **"Report on {line}" shortcut**: shown in the hero (sm and up) and in the report chooser. It uses the
  last line recorded by `LineStatusSheetService.openFor`, which stores it through
  `PreferencesService` as `lastReportedLineId`.
- **Accessible names**: rows and cards read "Details for {name}" and "Report delay on {name}". Pin
  toggles read "Pin {name}" / "Unpin {name}".

## Home: board folding, pin hint, and operator filter

- **Quiet-line fold**: lines that are in service, have no attention state, have
  `statusReportCount` 0, and are not pinned collapse into one expandable summary row
  (`isQuietLine` / `splitQuietLines` in `data/board-lines.util.ts`, store `quietLinesExpanded`).
  `network-board` takes a `foldQuiet` input (default true). The Pro lines widget sets it to false.
- **Pin hint**: dismissal is stored as `pinHintDismissed` in `PreferencesService`. Pinning stays local
  (`rosak:preferences:v1`) and works for anonymous readers.
- **Operator-family chips** on the board, filtered by `?op=` (`data/line-family.util.ts`, store
  `lineFamily` / `setLineFamily`). The family is the leading letters of the line code. This is a
  heuristic, because the schema has no operator field.
- **In-service chip**: a visible info glyph, plus a richer methodology entry. `line-pulse.vehicle-count`
  is rewritten, and `line-status.operator-family` and `line-status.last-report-hour` are new.
  `lastReviewed` is 2026-10-19.

## Home: Pro lines layout

- **Board / Table toggle** on the Pro lines widget. The table is `pro-lines-table.component` with
  `pro-lines-table.util`, sorted by `proLinesSort`. The layout is stored as `proLinesLayout`.

## Home: performance

- **Last Week is lazy**: `HomeStore.requestLastWeek()` runs on first activation of the tab. The tab count
  reads "–" until the first page lands. The 30s beat refreshes the section only once it has been requested.
- **History reads**: the sparkline and row reads run in `afterNextRender`, with a `networkHistoryPending`
  skeleton while they are in flight.
- **`PollingSource`** pauses while `document.hidden` and resumes on `visibilitychange`. Its timers are
  browser-only.
- **Board query** (`FrontPageLines`) drops `passengerStatusMessage`, plus `pulseLinks`
  `user`, `lines`, `voteScore`, `userVote`, `voteBreakdown`, `normalizedUrl` and `occurredAt`. The board
  read none of them.
- **Edge cache**: `src/server-cache-control.ts` sets `public, s-maxage=20, stale-while-revalidate=60` on
  `GET /` responses with status 200 only. It is wired in `server.ts`.
- **Concurrency**: `apphosting.yaml` `runConfig.concurrency` drops from 80 to 20. `minInstances` stays 0.
  Staging cold-start TTFB is still about 17s, with about 7s spent in SSR render. This is an open item.

## Known open items

- The expanded line row cannot show cause or direction, because the GraphQL schema has no such field.
- The Pro table's last-report column is hourly precision.
- The operator grouping is a heuristic.
- `e2e/home.spec.ts` still returns the dropped fields.
- The empty `catch` in the `PreferencesService` storage write is deliberate. It is best-effort persistence,
  and a failed write has no useful recovery path.
