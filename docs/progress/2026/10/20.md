# 2026-10-20

## About: legacy-row save fixes and editor draft normalization

- **Legacy rows no longer break the editor** (`e8075ac`): `draftFromDoc` defaults the personnel
  `name`, the social `name`/`link`, and keeps a missing `display` as hidden. Before this, a legacy
  row without a social name made `sanitizeDraft` throw on `.trim()` of undefined, which surfaced as
  a "Save failed" toast. A row without `display` was hidden on the public page but turned visible
  on the first admin save.
- **Stale comments corrected** (`e8075ac`): `filterAndSortProjects` sorts oldest-first, which the
  comment now says, and a dangling reference to a non-existent comment in `about.page.ts` is gone.

## About: accessibility and page meta

- **Heading structure and landmarks** (`dce1024`): one `h1`; team, tech stack and community are
  `h2`s; a new "Projects" `h2`. The search input has an `aria-label`, the error box is
  `role="alert"`, and the skeleton is `aria-busy` with sr-only status text.
- **Images and links** (`dce1024`): decorative `alt=""` on avatars and icons (the name sits next to
  them), sr-only "(opens in new tab)" cues, and focus-visible rings on card links, text links and
  the retired `<summary>`.
- **Editor labels** (`dce1024`): the aboutProject label is tied with `for`/`id`, and the Status
  select has an `aria-label`.
- **Page meta** (`dce1024`): `AboutPage` sets `description`, `og:title` ("MLPTF | About"),
  `og:description` and `og:type` through `Meta.updateTag`. The route is client-rendered, so this
  reaches JS-running crawlers only.

## About: empty and no-results states

- **Empty doc** (`a1bb17d`): a missing doc, or one with nothing visible, shows "Nothing has been
  published on this page yet." (`data-testid="about-empty"`) and hides the search box.
- **No results** (`a1bb17d`): a search that matches nothing shows "No results for “term”."
  (`data-testid="about-no-results"`, `role="status"`), with a "Clear" button (`clearSearch()`).
- **Editing a missing doc** (`a1bb17d`): `beginEdit()` starts from an empty draft, and Save creates
  the doc.

## About: admin editor saving and layout

- **Double-submit guard** (`7a4a33c`): a `saving` signal blocks a second `saveDraft()`. The button
  reads "Saving…" and both buttons are disabled.
- **Sticky save bar** (`7a4a33c`): the duplicated top and bottom Save/Cancel pairs became one sticky
  bottom bar.

## About: navigation and images

- **"On this page" jump nav** (`53198fd`): `sectionLinks` and `jumpTo(id)` render buttons for the
  sections with content (projects, team, tech-stack, community). The nav is hidden in edit mode.
  Scrolling respects `prefers-reduced-motion`, and focus moves to the section `h2`. A plain `#id`
  href would resolve against `<base href="/">`, so the page uses buttons.
- **Image dimensions** (`53198fd`): explicit `width`/`height` and `loading="lazy"` on avatars and
  icons. The header row wraps.

## About: tests

- **Component spec** (`2c20769`): new `about.page.spec.ts` (6 tests) covers the states, the a11y
  structure and the save flow. It mocks `firebase/app` and `firebase/firestore` with `vi.mock` and
  `vi.hoisted`, the pattern for Firestore-reading pages.
- **Util spec** (`2c20769`): 2 new `about-edit.util.spec.ts` tests.
