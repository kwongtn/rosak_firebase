## About: legacy-row save fixes and editor draft normalization

- **Legacy rows no longer break the editor** (`e8075ac`): `draftFromDoc` defaults the personnel
  `name`, the social `name`/`link`, and keeps a missing `display` as hidden. Before this, a legacy
  row without a social name made `sanitizeDraft` throw on `.trim()` of undefined, which surfaced as
  a "Save failed" toast. A row without `display` was hidden on the public page but turned visible
  on the first admin save.
- **Stale comments corrected** (`e8075ac`): `filterAndSortProjects` sorts oldest-first, which the
  comment now says, and a dangling reference to a non-existent comment in `about.page.ts` is gone.

## About: admin editor extracted into its own component

- **Editor component** (`362829c`): the admin form moved out of `about.page.ts` into
  `AboutEditorComponent` (`features/about/editor/`). It is form-only: `initial` (read once on init,
  so a later remote snapshot does not overwrite an open draft) and `saving` in, `submitted` (the
  `sanitizeDraft` result) and `dismissed` out. The page keeps persistence (`saveDoc`, the `saving`
  guard, toasts), visibility (`editMode`, `beginEdit`, `cancelEdit`) and a read-only `data`
  projection. The editor is loaded with `@defer (on immediate)`, so it is a separate chunk fetched
  only when an admin presses Edit, with a skeleton while it loads and a Close fallback on error.
  Template reads use `valueOf($event)` / `numberOf($event)` in place of `$any($event.target).value`.
- **Social edits hit the right person** (`8269470`): in the editor's nested socials loop, `$index`
  was the inner (social) index and was passed as the person index, so editing or removing a social
  changed the wrong person or was lost. The outer loop now aliases `let personIndex = $index`. Two
  new specs (the second person's social edit and removal) failed before the fix.

## Spotting: Most Recently Spotted tie-break

- **Line overview card orders by time, not just date** (this commit): `line-status-board` sorts the "Most Recently Spotted" card by `lastSpottingDate`, then by the new `lastSpottedAt` (`spotting.queries.ts` `VehicleRow.lastSpottedAt`, backed by the backend `Vehicle.lastSpottedAt` field). `lastSpottingDate` is date-only, so seven vehicles tied on 2026-10-18 and the card showed vehicle 110 over vehicle 151, which was spotted later.
- **Comparator returns 0 on ties**: the old `a > b ? -1 : 1` never returned 0, so tied rows were ordered arbitrarily by list order. The comparator now falls through to the secondary key and returns 0 only when both keys are equal.
- **Test**: `line-status-board.component.spec.ts` covers same-day vehicles ordered by `lastSpottedAt`.
