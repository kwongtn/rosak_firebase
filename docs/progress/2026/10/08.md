# 2026-10-08

## About: retired personnel + per-person service period

Frontend-only Firestore-CMS change on `/about` (`features/about/`) — no GraphQL document, no new
read, no backend change, no new dependency. The `public/about` personnel entries gain two additive
concerns: a **`retired` boolean** and a **month-precision service period**
(`startDate`/`endDate`, empty end = "Present"). Retired people move out of the active grid into
their own collapsed section under the same "About the team" heading, and every card gains a
humanized tenure line when a start date is set.

- **Model:** `Personnel` gains `retired: boolean`, `startDate: string`, `endDate: string`
  (between `display` and `order`, matching the visual grouping). Legacy docs lack all three.
- **Util (editor):** `draftFromDoc()` normalizes the new fields with `?? false` / `?? ""` on read;
  `sanitizeDraft()` coerces `retired ?? false` and trims both dates; `emptyPersonnel()` seeds them;
  `filterPersonnel()` re-normalizes on output (`retired: !!p.retired`, dates `?? ""`) alongside the
  existing `socials` normalization.
- **Util (display):** three new exported pure helpers, placed next to the filters with a fixed
  `MONTH_NAMES` table (no `Intl`/locale APIs, so output is deterministic):
  - `formatPeriod(startDate, endDate)` → `"Jan 2024 - Present"` / `"Feb 2020 - Nov 2022"`, `""`
    when the start is missing/unparseable;
  - `formatElapsed(startDate, endDate, now = new Date())` → whole-month tenure
    (`"Less than a month"`, `"1 month"`, `"2 years 3 months"`, omitting zero months; negatives clamp
    to "Less than a month"), `""` when the start is missing;
  - `formatPersonPeriod(person, now = new Date())` → the composed
    `"Jan 2024 - Present · 2 years 3 months"`, or `""` when there is no label.
    A private `parseMonth` accepts `"YYYY-MM"` leniently as `"YYYY-MM-DD"` (regex `/^(\d{4})-(\d{2})/`),
    validates month 1–12, and builds `new Date(year, month - 1, 1)` in **local** time — not
    `new Date("YYYY-MM")`, which parses as UTC. `now` is a parameter precisely so the tenure math is
    testable off a fixed clock.
- **Page:** `formatPersonPeriod` imported and wrapped by the `personPeriod(person)` template helper;
  `activePersonnel` / `retiredPersonnel` are two `computed()`s splitting `personnel` on `retired`;
  `NgTemplateOutlet` joined the component `imports` (`CommonModule`/`NgIf`/`NgFor` remain banned).
- **Template (public):** the team block now renders when `activePersonnel().length > 0 ||
retiredPersonnel().length > 0`. The existing card markup is declared **once** as
  `<ng-template #personCard let-person>` (hlmCard, avatar, name/title, description, socials) and
  instantiated through `[ngTemplateOutlet]` / `[ngTemplateOutletContext]` for both groups; the
  name/title column gains a period line only when `personPeriod(person)` is non-empty. Active people
  keep the 3-col responsive grid; retired people render inside a collapsed native `<details>`
  (`data-testid="personnel-retired"`, summary "Retired (N)") below it — the repo-wide GDPR
  `<details>/<summary>` accordion style.
- **Template (editor):** a "Retired" checkbox label sits beside the existing "Show" label with
  identical styling, and a native `type="month"` period row (start / "to" / end, with per-input
  `aria-label`s) follows the Title input. `updatePersonnel`'s value type already accepts
  `boolean | string | number`, so no signature change.
- **Backward compatible:** a legacy `public/about` doc without the new fields reads as
  `retired: false` + empty dates, so nothing is reclassified and no period line is drawn until an
  admin sets one.
- **Spec:** `about-edit.util.spec.ts` — the typed `doc` fixture personnel entries carry the new
  fields; the cast-based `draftFromDoc` test now asserts the three defaults; `sanitizeDraft` asserts
  a set/trimmed `retired`/`startDate`/`endDate` survive; `filterPersonnel` pins normalization of a
  legacy entry without fields. Three new describes run off a fixed `NOW = new Date(2026, 9, 8)`:
  `formatPeriod` (Present, explicit range, missing/garbage start, lenient day-precision),
  `formatElapsed` (2 months / 1 month / Less than a month / 1 year 3 months / 1 year / 2 years
  9 months / empty), and `formatPersonPeriod` (composed label + empty).

## app-nav: avatar-hint teardown race

Live-QA console error: `RuntimeError: NG0911: View has already been destroyed.` from
`app-nav-icon-tray.component.ts:307`, the `destroyRef.onDestroy(...)` inside the
`auth.whenReady.then` callback. `<app-nav>` is recreated per top-level navigation, so navigating
away before Firebase auth resolves leaves the callback running against an already-destroyed view.

- **Fix:** the callback's early return now also guards on `this.destroyRef.destroyed`. A tray
  destroyed before auth resolved never showed the hint, so the module-level
  `hasShownAvatarHintThisPageLoad` flag is deliberately left unconsumed — the next page's tray may
  still show it once.
- **Spec:** new `app-nav-icon-tray.component.spec.ts` — one focused test (single case by design,
  the flag is module-level): render, `whenStable()` so `afterNextRender` registers the pending
  `whenReady.then`, destroy the fixture, resolve the deferred `whenReady`, flush microtasks, then
  assert `setTimeout` was never called with the 2500ms hint delay. Red first: NG0911 unhandled
  rejection plus the hint timer armed; green after the guard.
