## not-found: the cat is one screen down, and the footer stays put while you go get it

The pet photo was the last thing on the page, directly under the buttons — so nobody who found a
dead link ever saw it, which was the entire point of fetching a random animal. And pinning the
footer to the viewport was already broken here: every page relies on the `min-h-screen` shell to
push the footer down, which only works while the page is **shorter** than the screen.

1. **The page is now two `min-h-dvh` screens.** The 404 block is the first, the photo is centred in
   the second, so the reveal is a screen's worth of scrolling. `dvh` over `vh` deliberately: on a
   phone `vh` is the viewport _including_ the space behind the browser chrome, so a `vh` section
   would put the photo off-centre by exactly the height of the URL bar the reader can't see. The
   per-section padding (`p-4 py-16` / `p-4 pb-28`) replaces the one shared padded wrapper the old
   single-section layout used — padding on the wrapper would have made each section `100dvh` _plus_
   its padding, which is precisely the drift `dvh` was chosen to avoid.
2. **The footer is pinned, page-scoped.** A flow footer on a deliberately two-screen page sits two
   screens down, i.e. never. It's wrapped in `fixed inset-x-0 bottom-0 z-40 bg-background` **on this
   page only** — no other page changes and the shared `AppFooterComponent` stays layout-agnostic
   (it still works for every other page's flow layout, and it only ever documented that as its
   intended use). `bg-background` is load-bearing: a fixed bar is transparent by default, so
   scrolling content would show through it. `z-40` sits below the nav's sticky `z-45` and the app's
   `z-50` overlay layer, matching the ladder `app-nav.component.ts` documents. The pet section's
   `pb-28` is the matching reservation so the centred photo can't end up behind it.
3. **The line above the photo is a hashed pool, not a literal.** `NOT_FOUND_MESSAGES` had a
   `"Meanwhile, here's a {kind}:"` caption; it's now `NOT_FOUND_SCROLL_LINES` — 8 deadpan lines in
   the same transit register ("Terminal station for the cat line. The driver does not make eye
   contact."), each with a literal `{kind}` token that `scrollLineFor` substitutes. Picked with the
   **same `hashString`** the 404 message already uses, so the rule stays "one dead URL, one joke"
   rather than becoming a second mechanism, and no `Math.random()` — which would reintroduce the
   SSR/hydration flash the hash exists to prevent. `hashString` moved from the page into
   `not-found-messages.ts` because both pickers now share it.

## home: the refresh control says "Updating" for the beat's own refresh too

The beat's refresh was invisible. Every 30s the countdown silently reset and the page quietly
re-read its three resources; only a click ever put a label up, so a reader watching the beat could
watch the page change underneath them with no signal at all. Commit `35b8c08`.

1. **The label tracks `isRefreshing`, not the click.** `_isUpdating` is now raised for ANY refresh
   the page is visibly doing — the click, the 30s beat, a reload the edit sheet or the retry banner
   triggers — because the store's `isRefreshing` is the only member that can see a reload
   (`graphqlResource.isLoading` is pristine-first-fetch-only). The two rendered instances both show
   it: they share the store's single beat, and only one is visible per breakpoint.
2. **The pristine initial load is the ONE exclusion.** A first paint is not a refresh, so the effect
   derives the exclusion from the stores' pristine-only flags,
   `store.isLoading() || store.isLoadingLastWeek()` — ORed because they cover different resources
   (`isLoading` is lines + today feed, `isLoadingLastWeek` is the section's own first fetch). Because
   both are pristine-only, the exclusion can never fire again after the first load.
3. **"Updated" stays click-armed.** `_showRefreshed` is unchanged: a passive reader is never told
   "just refreshed" on a timer they did not set. The click-arm machinery therefore now belongs to
   the _confirmation_, not the label — the settle edge and the `ARM_EXPIRY_MS` stale-arm expiry are
   still the only two exits out of an armed window, and the settle edge still runs _before_ the
   `hasError` early-return so an errored refresh drops the label.

## console/links: rails instead of offsets, eight columns instead of ten, and buttons that wait for their own precondition

The morning wave made the tree's verbs _usable_ (one tick to nest, one click to unblock the queue). This
wave makes them **legible** — and, for the two that were previously "present but permanently dead" on
the default Pending view, it stops drawing them until they mean something. Four refinements to the same
table, one component file plus its spec (`dcde12a`), no backend or schema change.

1. **Nesting is drawn as RAILS plus a tint, and the rails ARE the indent.** The URL cell's
   `data-testid="link-depth"` wrapper no longer carries `[style.padding-left.px]`; it renders
   `depthRails(link)` — one entry per ancestor level, values never read, only the length — as that many
   `data-testid="link-rail"` spans, each `shrink-0 self-stretch border-l` so it runs the row's full
   height, with an `aria-hidden` `data-testid="link-elbow"` `h-6 self-start border-t` stub on the
   **last** rail only. A bare gap reads as an indent only while you are looking at the gap; three levels
   of nothing read as three unrelated distances, and the elbow is what turns a vertical rule into "this
   one hangs off that one". `DEPTH_INDENT_PX` goes 16 → **20** and is now **bound** into both spans —
   `[style.width.px]="depthIndentPx"`, plus `[style.margin-left.px]="-depthIndentPx"` on the elbow to
   pull its stub back onto the last rail's own line (`9db1259`) — rather than a `w-5`/`-ml-5` pair, so
   the constant really is the only place the rail step is defined: a class would render identically and
   be a second definition no grep for the constant could find. The rails deliberately carry **no
   `gap`** (a gap would fall between two rails and break the line a reader follows downward). A child row
   additionally gets `[class.bg-muted/40]` on the `<tr>`, over `hover:bg-muted`: the rails say _which_
   ancestor, the tint says the weaker row-wide "this is not a root", and it survives the row being scanned
   rather than its left margin being counted. Hover still wins, because `bg-muted` is a stronger value of
   the same token and comes later in the class list.
2. **The table is eight columns, and both merges are about the row rather than about space.** The
   `N links` chip moved **into the URL cell**, as the anchor's second line in a `flex-col items-start` —
   so its left edge _is_ the URL text's left edge by construction, with no `margin-left` to re-derive
   every time the rail width, the chevron reserve or a gap changes — and its `""` answer now renders
   **nothing** rather than an em dash, because an ungrouped link is the overwhelming majority of the
   queue and a column of dashes was the loudest thing on the row. `Occurred` merged into the
   **Submitted** cell as a
   `text-xs` line drawn **only** when `link.created !== link.occurredAt`, labelled in full
   (`Occurred Aug 1, 2026 08:30`) — a back-dated report is the only case where the two clocks disagree,
   and a second identical line everywhere else is noise an admin learns to skip. That test is an exact
   string compare on purpose: with `strictNullChecks` off, a payload missing `occurredAt` would parse to
   `NaN` through `new Date()` and `NaN !== NaN` is **true**, so the "smarter" spelling would print
   "Occurred Invalid Date" on exactly the rows a fixture under-specified. The chevron reserve span gained
   `data-testid="chevron-placeholder"`, because the rails are `aria-hidden` and a spec asking "is the
   chevron's width reserved here?" cannot ask for `aria-hidden` and mean one specific element. Skeleton
   rows and both `colspan`s are 8.
3. **The two actions that need a precondition are not drawn until it holds.** Move up / Move down sit
   inside `@if (queueIsComplete())` and Nest under… inside `@if (nestSelectionReady())`, so the default
   Pending queue no longer shows a dead greyed pair on every row and the nesting affordance appears with
   the first tick — which is the toolbar hint being discharged, not a new thing to discover. 🔴 Nothing is
   weakened: `canMoveUp`/`canMoveDown`/`canNestUnder`/`reorderSiblings` all still refuse on the same
   conditions, because a programmatic caller reaches past the template. Once drawn they come back fully —
   disabled at the two ends of the stored run, and on the ticked rows for nesting (a cycle the server
   rejects as a unit) — each with its reason on hover.
4. **"Show all links" is never disabled, and its click cannot be swallowed.** The button used to grey
   itself out mid-load, which made the one action that can unblock the queue look unavailable exactly when
   an admin reaches for it; it is now never disabled and is right-aligned (`ml-auto shrink-0` against a
   `flex w-full` hint whose sentence is `flex-1 min-w-0`). A never-disabled button is only honest because
   the handler cannot drop the click: a `load()` arriving mid-load parks `reloadQueued`, and
   **`finishLoading()` is the ONE place `isLoading` drops** — called from `load()` and from all six
   mutation verbs (`sendGrouping`, `ungroupLink`, `reorderSiblings`, `approveLink`, `setLinkStatus`,
   `markCompleted`). The drain therefore cannot live in `load()`'s own `finally`: six of the seven verbs

   - 🔴 `fetchLinks` also **snapshots the completeness answer before its first `await`**. The applied

## console/links: the three tree verbs become icons, and the second clock line is minute-precise

Two follow-ups to the same queue, both from looking at the rendered table rather than the code (`2f5bd09`).
No backend or schema change.

1. **Move up / Move down / Nest under… are ICON-ONLY `size="icon-sm"` buttons.** They used to spell out
   their labels, and those words are what made the action cell wrap to two lines and pushed Delete toward
   the edge of a row that already had six other controls on it. An arrow glyph carries none of that meaning
   on its own, so each button states it **twice from one source**: `[attr.aria-label]` (what a screen
   reader announces) and `[attr.title]` (what a mouse user reads on hover) both bind the **same class
   field** — `moveUpHelp` / `moveDownHelp` / `nestHelp`, declared once each as the `??` fallback of its
   title. The title is the blocked reason whenever there IS one (`moveBlockedReason` /
   `nestBlockedReason`) and the help copy only while the action is live, so the two states are mutually
   exclusive and a live button is never silently mute; the reason stays a `null`-returning **method**
   because it is per row and per queue state, while the help copy is constant. `attr.title` is kept even
   though both branches are now non-null, because `moveBlockedReason` is typed `string | null` and the
   guard has to survive whoever widens it next. `size="icon-sm"` (a `size-7` square) rather than
   `size="sm"`: an icon button has no text to give it width, and the square keeps the row height and its
   neighbours' height identical. Each inline feather-style `<svg>` carries `aria-hidden` — the glyph is
   decoration beside a labelled control, so announcing it would read the icon's shape out loud after the
   sentence that already names the action. The **gates are untouched**: the pair is still inside
   `@if (queueIsComplete())`, Nest under… still inside `@if (nestSelectionReady())`.
2. **"Same instant" for the two clocks is now SAME MINUTE, and the rule lives in a util.** The cell's
   gate moved from `link.created !== link.occurredAt` to `!isSameMinute(link.created, link.occurredAt)`,
   because **the rendering is minute-precision**: both lines go through `MMM d, y HH:mm`, so the seconds
   are gone before the admin sees either one. An exact-instant test prints `Aug 1, 2026 09:00` directly
   under an identical `Aug 1, 2026 09:00` on any row whose two clocks differ only below the minute — and
   two indistinguishable lines are worse than either showing one line or showing two that genuinely
   differ, because the admin cannot tell which mistake they are looking at. Nothing about a payload has to
   be broken to produce that: two `DateTime`s written microseconds apart, or a value re-serialised
   through a path that normalised the seconds, are enough. It is a rule about **rendering**, not about the
   data.
   - New pure util **`src/app/features/console/insiden/data/same-minute.util.ts`**
     (`isSameMinute(a, b)`), re-exposed on the component so the guard cannot be re-invented inline in a
     template binding. The **exact-string fast path comes first**, and it is not a micro-optimisation: it
     is the only branch that can be right about a payload it cannot parse, and the backend's
     `occurred_at = created` for a submitter who stated no event time means the overwhelming majority of
     rows never depend on the host TZ at all.
   - ⚠️ **Truncation, not rounding** — `Math.floor(ms / 60_000)` buckets each instant into the minute it
     falls in, so `09:00:59` and `09:01:00` are different minutes. Rounding would push the first up into
     the second and report a whole-minute disagreement as agreement.
   - 🔴 **An unparseable side returns `false`, so `NaN` never decides it.** With `strict` /
     `strictNullChecks` off, a fixture or a stale payload can hand the comparison two unparseable values,
     and `NaN !== NaN` is true — a naive `a === b || parse(a) === parse(b)` would report different
     instants as the same and render the line as `Invalid Date`. Returning `false` can only ever **ADD** a
     (harmless, redundant) line, never suppress a real one; the identical-strings fast path is
     deliberately exempt, because two identical invalid strings really are the same value.
