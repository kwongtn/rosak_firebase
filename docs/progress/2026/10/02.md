## home: the refresh control says "Updating" for the beat's own refresh too

The beat's refresh was invisible. Every 30s the countdown silently reset and the page quietly
re-read its three resources; only a click ever put a label up, so a reader watching the beat could
watch the page change underneath them with no signal at all. Commit `35b8c08`.

1. **The label tracks `isRefreshing`, not the click.** `_isUpdating` is now raised for ANY refresh
   the page is visibly doing — the click, the 30s beat, a reload the edit sheet or the retry banner
   triggers — because the store's `isRefreshing` is the only member that can see a reload
   (`graphqlResource.isLoading` is pristine-first-fetch-only). The two rendered instances both show
   it: they share the store's single beat, and only one is visible per breakpoint.
2. **The pristine initial load is the ONE exclusion.** A first paint is not a refresh, so the effect
   derives the exclusion from the stores' pristine-only flags,
   `store.isLoading() || store.isLoadingLastWeek()` — ORed because they cover different resources
   (`isLoading` is lines + today feed, `isLoadingLastWeek` is the section's own first fetch). Because
   both are pristine-only, the exclusion can never fire again after the first load.
3. **"Updated" stays click-armed.** `_showRefreshed` is unchanged: a passive reader is never told
   "just refreshed" on a timer they did not set. The click-arm machinery therefore now belongs to
   the _confirmation_, not the label — the settle edge and the `ARM_EXPIRY_MS` stale-arm expiry are
   still the only two exits out of an armed window, and the settle edge still runs _before_ the
   `hasError` early-return so an errored refresh drops the label.

- **Tests**: `npx prettier --check .` clean; `npm test -- --no-watch` — **105 files / 1241 tests**
  passed, 0 failed (baseline before this change on this branch: 105 / 1239); `npm run build` exit 0.
  New/changed specs, all in `home-refresh-control.component.spec.ts`: the automatic-refresh spec
  flipped from "confirms nothing" to "shows **Updating** while in flight, never confirms"; a new
  **four-phase** spec pins the pristine-load exclusion across all three page resources, including the
  last-week half of the OR; a new **real-store** spec drives the actual 30s `PollingSource` timer and
  asserts the label against the real store (mount stays on the countdown, the beat says Updating, it
  settles with no confirmation); and the store-re-entry spec was **split into its two phases**,
  because `start()` on a retained store is itself a refresh and now says so.
- **Browser-verified, not just jsdom**: dev server with the beat driven at 5s through its own
  `setIntervalMs`, no click. The control went **UPDATING** on the tick, returned to the countdown
  when it settled, and **never** showed an "Updated" confirmation; a pristine load stayed on its
  countdown throughout.
- **Docs**: `docs/components/home.md` (the three-state passage — only the first state is
  click-gated, and the pristine load is its single exclusion; `HomeStore.isRefreshing`'s
  consumer-side exclusion; the `refresh-control` extension-point bullet, whose "armed by the CLICK"
  rule was the thing this change superseded).
- **Methodology registry**: checked `src/app/core/methodology/` — a refresh label is presentation,

## ui/ad-slot: the disclosure caption is a pill with its "i" on the right, and only the pill is a hotspot

A visual complaint on the `Advertisement` caption of every ad unit: the "i" glyph sat to the **left**
of the wording, the trigger had no padding, and because `InfoPopover` tracks hover on its **host** —
which was a full-width stretched flex child of the unit's `flex flex-col` wrapper — the _entire row_
was a hover target, so the panel popped open from anywhere above the creative.

1. **Glyph placement is now a shared, documented extension point.** `InfoPopover` gains
   **`iconPosition: "start" | "end"`** (default `"start"`, so the methodology page and the home
   status chips are pixel-identical). The glyph is rendered by one of two `@if` branches around the
   projection slot, so `"end"` really moves the node in **DOM order** rather than only in painted
   order, and a single `glyphClasses` string keeps the two branches from drifting. One glyph either
   way — placement swaps, it never duplicates.
2. **Padding belongs to the thing the pointer can hit.** `InfoPopover` gains **`triggerClasses`**,
   classes merged _after_ the button's base classes (never replacing them, so `cursor-help`, the
   focus ring and `rounded-full` survive). `AdSlotComponent` passes
   `px-2 py-0.5 transition-colors hover:bg-muted/60` as `captionTriggerClasses`.
3. **The host is shrink-wrapped instead of stretched.** `class="justify-center"` →
   `class="self-center"`: `align-self: center` is what makes the flex item fit its content, so the
   popover host — and therefore the hover area — is now just the caption pill. The caption stays
   row-centered, so the `align="center"` panel lands exactly where it did before.

- **Verified**: `npx prettier --check .` clean; `npm test -- --no-watch` — **105 files / 1239 tests**
  pass (baseline before this change on this branch: 105 / 1236). New/changed specs:
  `info-popover.spec.ts` (glyph leads by default and trails with `iconPosition="end"` in real DOM
  order, one glyph only, badge classes intact on either branch; `triggerClasses` merged and the base
  classes kept) and `ad-slot.component.spec.ts` (popover host is `self-center` and no longer
  stretched, glyph after the "Advertisement" text, pill padded).
- **Browser-verified, not just jsdom**: dev server + `?adpreview=1` on `/about`. Wrapper 546px wide,
  popover host **127px** and still row-centered (host centre 361px = wrapper centre); trigger padding
  `2px 8px`; the label ends at x=397 and the glyph starts at x=400 (right of the text). Real pointer
  moves: hovering the pill opens the panel; hovering the same row 118px to the left — hit-tested onto
  the wrapper `div` itself — does **not**. `InfoPopover` opens on `mouseenter`, so the real-browser
  check is what proves the hotspot shrank; jsdom can only assert the classes.
- **Docs**: `docs/components/methodology.md` (`InfoPopover`'s input list gained `iconPosition` +
  `triggerClasses`, and the "new `InfoPopover` consumer" extension point now says to shrink-wrap the
  host when only a small pill should be the hotspot).
- **Methodology registry**: checked `src/app/core/methodology/` — a caption's glyph side and padding
  are presentation, not a documented metric or threshold, so there is no `MetricDoc`/`lastReviewed`
  to add.
- **Backend**: untouched — no GraphQL contract, model or task involved.

## console/profile: "Nest under…" needs ONE tick, and the console reorder action is one click away

A browser report — "move up / move down / nest under is never clickable" on `/console/links` — turned
out to be two frontend gates, both fixed (`84b9202`), with no backend or schema change.

1. **Nest under reused the untargeted verb's minimum.** `canGroupSelection()` (>= 2 distinct ids) gated
   `canNestUnder`/`nestSelectedUnder` on the console and `_nestReason` on My Submitted Links. That
   minimum is only true of `groupSocialMediaLinks`' **no-target** mode, where the selected link is
   elected as its own root (a no-op). The **same mutation with a `parentId`** makes the ticked rows
   direct children, so one link is a real write — the way a conversation gains its first child — and
   the backend nests single ids throughout (`_normalize_ids` refuses only the empty list). The shared
   `link-thread-selection.util.ts` gains **`canNest` (>= 1 distinct id)**; both surfaces use it, and
   the console's toolbar hint now has its zero-tick and one-tick spellings instead of one two-tick rule
   that under-sold nesting.
2. **The console's reorder state was unreachable from the default queue.** `queueIsComplete` correctly
   refuses any filtered page (a partial permutation is silently completed server-side), but the queue
   **defaults to Pending**, so Move up/down are off on first load — and the hint's "clear the filters"
   instruction had no action behind it: `Reset` restores the queue default, which IS Pending. The
   `reorder-hint` now carries **`reorder-show-all` ("Show all links")**, which cancels the debounce,
   clears every live control and every applied field, sets Status to All and reloads; `resetFilters()`
   and `showAllLinks()` share one `applyQueueFilters(completed)` snapshot writer so they cannot drift,
   and the disabled button's tooltip names the action. The expanded-state and the two reorder gates
   are unchanged — only reachability.

- **Verified**: `npx prettier --check .` clean; `npm test -- --no-watch` — **105 test files / 1236
  tests** (pre-change baseline on this branch: 105 / 1229); `npm run build` exit 0. New/changed specs:
  `link-thread-selection.util.spec.ts` (the new `canNest` describe: empty false, one true, larger
  true, distinct-count semantics), `links.component.spec.ts` (one-tick nest enablement and the
  cycle target, the single-link nest payload, the `Show all links` DOM click asserting the
  `completed: undefined` wire query and the flag turning `queueIsComplete` on), and
  `my-links.component.spec.ts` (one-tick nest enablement; the single-row nest payload and the resulting
  one-level indent).
- **Browser-verified, not just jsdom**: built the dev bundle and drove `/console/links` in real
  Chromium against the e2e mock — default moves disabled → one "Show all links" click enables them and
  removes the hint → one tick enables Nest under on the unticked rows → clicking fires
