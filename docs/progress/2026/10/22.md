## [2026-10-22] core: one auth interceptor for every backend request

- F191: `authInterceptor` (`src/app/core/http/auth.interceptor.ts`, registered in `app.config.ts`) signs every request to `backendUrl` or `backendGraphqlUrl` with a signed-in viewer's `firebase-auth-key` and sets `transferCache: false` on it (`79a5195`). A signed-out viewer's request goes out at once and unsigned. A failed token refresh fails the request with Firebase's error before anything is sent, as the per-call-site `idToken()` calls did. The token is asked for synchronously when the request is made, so a request made just before a sign-out carries the old session's token.
- F191, where it lives: `core/http`, not `core/auth`. `app.routes.spec.ts` forbids `core/auth` from `main`, and importing `AuthService` there would put Firebase Auth (about 91 kB) into the initial bundle. `AuthService`'s constructor writes itself into the root `AUTH_SESSION` token (a signal of `Pick<AuthService, "isLoggedIn" | "idToken"> | null`), so the eager interceptor never imports the lazy service. Every page's nav injects `AuthService`, so it is always started; before it starts, a request goes out anonymous.
- F191, API: the `ANONYMOUS` `HttpContextToken` opts a request out. `graphqlResource(fn, { authenticated?: boolean })` is new: a read is anonymous by default, and `authenticated: true` waits once for `auth.whenReady` and then signs. It does not refetch on a sign-in or sign-out, so a `requestFn` that must follow the viewer reads `auth.user()` or `isLoggedIn()` (`6227c64`). `GraphQLClient.request` no longer sets `transferCache` itself, and `GraphQLRequestOptions.anonymous` sends an imperative read with `ANONYMOUS` (`0478a8e`).
