## home/hero: the top edge is the status line, and the countdown moved onto the headline row

The Phase-0 **brand-orange accent rail is gone**. In its place the hero's top edge is a full-width
track whose fill is the fraction of the poll beat left, wearing the network's own tone; the `h1`
beside it wears the same tone as text. "Refreshing in Ns" moved out of the desktop-only bottom-right
`hidden justify-end lg:flex` corner into `hero-refresh-slot`, the **rightmost cell of the headline
row at every width** — "Refreshing in 12s" modifies the sentence above it, and the old gate hid the
control entirely at the mid widths.

1. **The tone is one pure rule, and the colour and the words cannot disagree.** New `NetworkTone` +
   `networkTone(total, needsAttentionCount)` in `data/network-summary.util.ts`, beside
   `summarizeNetwork` and derived from the SAME two counts the headline sentence is built from:
   `unknown` (no lines read) neutral, `normal` (0 needing attention) green, `degraded` (needs
   attention ≤ **half**) orange, `critical` (> half) red. Half is the CEILING of `degraded`, not the
   floor of `critical` — at exactly half most riders are still on working trains, and painting that
   the same alarm red as a broadly-down network trains readers to ignore red. Seven cases in
   `network-summary.util.spec.ts`, including `(16, 8)`, `(16, 9)` and `(4, 3)`. The shade choices stay
   in the component (`_headlineClass` / `_lineClass`, dark-mode aware) because which orange is a design
   decision, not a fact about the network — but the Tailwind strings are full literals so the compiler
   sees them.
2. **`hero-countdown-line` is drawn from `secondsRemaining()/intervalMs()`, never
   `percentRemaining`.** `refreshNow()` resets `secondsRemaining` immediately while `percentRemaining`
   only moves on the next 1s tick, so the latter lags a manual refresh by a second and would refuse to
   refill while claiming to be full. Both ends are clamped (paused → 100%, overshot → 0%); on the
   server `secondsRemaining` is `0`, so the SSR paint is a 0%-wide neutral line the client fills on
   first binding — the same swap the removed ring did, and the reason there is no hydration guard.
   `duration-1000 ease-linear` matches the tick and carries `motion-reduce:transition-none`.
3. **The hero card no longer clips.** `overflow-hidden` is gone from its `<section>` because the
   headline popover, the tile popovers and the menu panel are all positioned inside it and must escape.
   The two decorative edges round themselves instead: the countdown track `rounded-t-2xl`, the colour
   ribbon `rounded-b-2xl`, each keeping its own `overflow-hidden` to clip only its own fill/segments.
4. **`HomeStore` is injected for the beat alone.** The hero authors no request and starts no timer; it
   reads the same route-scoped store, in the same injector tree, that `HomeRefreshControlComponent`
   reads. Both specs that render the hero already mock `polling`.
5. **Default theme, not brand orange.** "Report a delay" (lost `bg-brand text-brand-foreground
hover:bg-brand/85`) and "Live map" (lost `text-brand`) now take the `hlmBtn` defaults.

## home/refresh-control: text only, and a tooltip you can actually read

Both SVGs are gone — the countdown ring (`line-refresh-ring` / `-ring-arc`) and the reverse-spun
"Updating" spinner — along with the ring machinery (`RING_RADIUS`, `RING_CIRCUMFERENCE`, `_ringOffset`)
and `computed` from the `@angular/core` import. The green check beside "Updated" is the only graphic
left. The countdown's _indicator_ is now the hero's top status line, so the beat is stated twice in two
registers instead of a widget drawing itself inside a label.

The three-state machine is untouched and still load-bearing: **Updating** (tracked by `isRefreshing`,
pristine initial load the only exclusion) → click-armed **Updated** → the countdown, with the Updating
branch first and the click arm torn down on both exits. The tooltip moved `z-10` → `z-50` and now
closes **300ms after `mouseleave`** (cancelled on re-enter, cleared on destroy) — the same grace
window `InfoPopover` and the nav use, because a tooltip that disappears as the pointer moves toward it
is unreadable.

## home/hero sparkline: empty and failed now hold the chart's height

The `<figure>` is unconditional. `_visible()` is renamed `_plotted()` and kept **verbatim** — its false
branch now renders a dashed `h-10` placeholder (`network-sparkline-empty`) instead of nothing, so bars
and placeholder can never both be present or both absent. Two rules survive: a **failed** read must not
draw the store's stale buckets (yesterday's picture drawn as today's is worse than an honest empty box),
and `networkHistoryFailed` — never `HomeStore.hasError()` — stays the widget's own signal. The two quiet
states read differently ("Activity data unavailable" vs "No activity reported yet") because only one is
a failure the reader may hit again, and the hour-axis row is unconditional too (empty strings and all) so
the widget's total height is identical in all three states.

## ui/info-popover: panels moved to the app overlay layer

`InfoPopover`'s panel `z-20` → **`z-50`**, the app overlay layer — above the page nav's `z-[45]` and the
sticky mobile action bar's `z-30`. No behaviour change: `HOVER_CLOSE_DELAY_MS` stays 300. Combined with
the clipping removal above, this is what makes a popover panel escape its card AND stay above the
chrome; the ladder is now `nav z-[45] < overlay z-50`. Recorded in `MISTAKES.md`.

## Round 2b (follow-up): the edge lines clip, the fill snaps, the headline counts in service

Three verified reports from the live page, one worker, docs + `src` only. Evidence (plan § Round 2b in
`.omo/plans/home-page-polish-round2.md`, findings in `.omo/notepads/home-page-polish/round2b.md`): full
suite **131 files / 1782 tests passed, 0 failed**, `prettier --check src` clean, `npm run build` exit 0,
and a live browser pass — headline "All 14 lines running normally" green, tile still "2 Needs
attention", fill at `transition-duration: 0s`, both edge lines inside the card's corners.

1. **Both decorative edge lines are clipped by ONE card-shaped overlay.** Why: each line is 4px tall and
   CSS clamps a corner radius to its own box, so the lines' `rounded-t-2xl` / `rounded-b-2xl` collapsed
   to ~4px and their square ends poked outside the card's 18px corners. The card itself still carries NO
   `overflow-hidden` — that would clip the popovers round 2 freed — so the clip lives on the card's FIRST
   child: `pointer-events-none absolute inset-0 overflow-hidden rounded-2xl`, `aria-hidden`, holding
   both `hero-countdown-line` and `hero-ribbon` (neither keeps any `rounded-*` of its own).
   **Supersedes item 3 above** ("the two decorative edges round themselves instead"); the line-pulse
   card/row rail rule is untouched.
2. **The countdown fill SNAPS — the width transition is gone.** Why: the width is rewritten once per
   second, so `transition-[width] duration-1000 ease-linear` made every refresh read as the line
   _flowing_ back to full — a slow sweep with no meaning on a countdown. The spec now pins the ABSENCE
   of `transition-[width]` and `duration-1000`. **Supersedes the closing line of item 2 above** (the
   `secondsRemaining`/`intervalMs` derivation itself is unchanged and still correct).
3. **The headline and the tone count IN-SERVICE lines only.** Why: the live read is 14 `ACTIVE` + LRT SAL
   `TESTING` + Skypark `DEFUNCT`, and "14 of 16 lines running normally" in orange dresses a permanent
   property of the network as an incident nobody can wait out. New pure `isInService(line)` +
   `NetworkSummary.inService { total, needsAttentionCount }` in `data/network-summary.util.ts`;
   `summarizeNetwork` filters through it, `_tone` now calls
   `networkTone(summary.inService.total, summary.inService.needsAttentionCount)`, and a non-empty read
   with nothing in service gets its own headline, `"No lines in service"`, instead of the empty-read
   `"No live line data yet"`. 🔴 **Two explicit user decisions:** (a) exclude **exactly** `TESTING` and
   `DEFUNCT` — every operational status, including `PARTIAL_*` and `TOTAL_DISRUPTION`, still counts; (b)
   the scoping covers **headline + tone only** — the stat tile, the callouts, `worstLine`, the board's
   three-group partition and `total` / `normalCount` / `needsAttentionCount` keep counting ALL lines, so
   the green "All 14 lines running normally" sits beside an unfiltered "2 Needs attention" on purpose.
4. **Methodology registry (round 2b's own follow-up).** `network.lines-normal`'s definition now
   documents the in-service scoping AND the tone's green/orange/red rule — it is the string the hero's
   headline popover renders — under a new `REVIEWED_AT_HEADLINE_IN_SERVICE = "2026-10-05"` constant with
   that metric's `lastReviewed` bumped (the `line-status` SECTION's own date deliberately not bumped;
   sharing an existing constant would have claimed a review of its neighbours).
   **Supersedes the round-2 "Methodology registry" note above**, which was the correct conclusion for
   round 2's own (presentation-only) change.

## Round 2b · gradual refinement: the fill tweens again, and snaps only on reset

A second pass on entry 2 above, from the user watching the line move. **Why:** with the transition
removed, the fill stepped once per second and then jumped to full on a refresh — the user wants the
countdown to read **gradual (no stepping)** while still not "flowing" back up after a beat reset.

**What** (`hero/home-hero.component.ts` only):

- The width transition is back on the fill — `transition-[width] ease-linear` +
  `motion-reduce:transition-none` — so each once-per-second width write is interpolated across the
  next second: continuous movement while the beat counts down.
- A jump UP is still instant: `[style.transition-duration]="_snapToFull() ? '0s' : '1s'"` on the same
  span. `_snapToFull` is a signal seeded `true` (so the 0%-wide SSR paint fills without sweeping up
  over hydration), and a constructor `effect` re-derives it on every read of `secondsRemaining` by
  comparing against the previously observed value — `seconds > previous` (or a first read) means a
  (re)start (the beat's own reset, `refreshNow()`, a store resume) and renders at `0s`, i.e. snaps to
  full; a count-DOWN (`seconds <= previous`) gets the normal 1s tween.

🔴 **Supersedes entry 2 of Round 2b above** ("the countdown fill SNAPS — the width transition is
gone"): true when written, now **gradual with instant reset**. The concern that entry named (an
un-qualified tween makes every refresh read as a sweep back to full) is exactly what the
`_snapToFull` edge carries, so neither half of the reasoning is lost.

Evidence (live): width samples move ~5.5px per 150ms continuously while counting down; immediately
after a refresh click the fill reads 100% at `transition-duration: 0s`, and `1s` again on the next
tick.

## Round 2c (follow-up): the countdown moves back into the click-to-action control

**Why:** the user wanted the countdown indicator **unified with the click target again** — round 2
had split the beat across two registers (a shrinking top line above, plain words inside the button)
and round 2b refined that split; round 2c puts it back in one place: a **static network-tone line**
on the top edge, and the **donut + spinner + check** inside the refresh control.

**What changed** (`src/` — hero and refresh-control components + their specs only):

1. **The hero's top line is decoupled from the beat.** `hero-countdown-line` → **`hero-status-line`**:
   a static, full-width hairline wearing only the network's TONE (green/orange/red, neutral before
   the first read), still inside the card-shaped clipping overlay with the ribbon. `_countdownPct`,
   `_snapToFull`, the constructor's snap `effect` and the width/transition bindings are **deleted**,
   and with them the hero's `HomeStore` inject — the hero holds no store at all now (the refresh
   control and the sparkline inject it themselves). Its class is the whole binding: a beat tick,
   reset or pause never writes to it.
2. **The refresh control regains the click-to-action donut** (restored from `6730e2e`, the last
   commit that had it): countdown state = SVG ring (`line-refresh-ring` / `line-refresh-ring-arc`,
   `-rotate-90`) whose arc **drains** as the beat runs down — full at reset, empty at zero — from
   `stroke-dashoffset` computed over `secondsRemaining()/intervalMs()` (never `percentRemaining`,
   which lags a refresh by a tick), guarded and clamped at both ends, 1s linear transition +
   `motion-reduce:transition-none`. Updating = the counter-clockwise spinner (direction inside the
   `animation` shorthand, `motion-reduce:[animation:none]`, no inline `animation`) + "Updating";
   Updated = the green check + "Updated". Round-2 tooltip wins untouched (300ms close, `z-50`), whole
   arm/expiry/confirmation state machine unchanged.
3. **Arc colour:** `text-primary` — the **default theme**, not the pre-round-2 `text-brand` — flagged
   to the user, consistent with the CTA row's brand-class removal in round 2.

🔴 **Supersedes** the round-2 and round-2b claims about the countdown living in the top status line:
the "fill interpolates / gradual tween / `_snapToFull` snap" passages, the round-2 "text-only
control" claim, and round-2b item 1's mention of `hero-countdown-line` inside the overlay (the
overlay itself is unchanged — only the testid and the fill's bindings moved). The tone rule
(`networkTone`, in-service scoping), the overlay clip, the tooltip, the state machine and the sparkline
are all untouched.

**Evidence:** full suite **131 files / 1785 tests passed, 0 failed**, `npm run build` exit 0,
`prettier --check` clean on every touched file. Live in the browser: the ring's
`stroke-dashoffset` drains **43.36 → 47.13 → 50.90** while the countdown reads 7s → 5s → 3s; the top
line sits at full width with an **empty `style` attribute**; "Updating" shows the spinner SVG carrying
`[animation:spin_3s_linear_infinite_reverse]` with an empty inline `animation`.

## Round 2d (follow-up): the ring is 22px again, in one fixed glyph slot

**Why:** the ring round 2c restored had **no explicit `width`/`height`** — only a `viewBox` — so it
rendered at the CSS initial size and came out a **112×112px "big spinner"** in the hero's headline
row (button 112×136). The user rejected it; the fix is to imitate the tracker side panel exactly
rather than size it by eye.

**What changed** (`src/` — `refresh-control/home-refresh-control.component.ts` + `.spec.ts` only):

1. **Ring = `CountdownRingComponent`'s geometry, explicit size included.**
   `width="22" height="22" viewBox="0 0 22 22"`, circles at `cx/cy="11"`, `r` still bound to
   `RING_RADIUS` (9 — the `RING_CIRCUMFERENCE` 56.55 math untouched), `stroke-width="2.5"`, track
   `class="text-muted-foreground/20"` (the `stroke-opacity="0.25"` attribute is gone), arc keeps
   `text-primary` + `transition-[stroke-dashoffset] duration-1000 ease-linear` +
   `motion-reduce:transition-none` + round cap + both testids, svg keeps `-rotate-90`. The ring now
   has its OWN 22-unit viewBox; the spinner and check keep the app-wide 24-unit one.
2. **ONE always-rendered fixed slot** — `inline-flex size-7 shrink-0 items-center justify-center`
   wraps the leading glyph of ALL THREE states (ring / spinner / check) and nothing else: the
   tracker rows' `LayerChecklistComponent` "fixed-size slot, contents vary" pattern. This button
   shrink-wraps to its visible content, so without a constant slot a 22px ring → 14px spinner → 14px
   check would re-flow the row (and its label) on every state change. Labels
   (`line-refresh-updating`, `line-refresh-confirmation`, `Refreshing in Ns`) stay direct children
   of the button, right after the slot; tooltip arm (300ms / `z-50` / touch toggle) unchanged.
3. **Spinner at the tracker checklist's 1s** — `spin_3s` →
   `[animation:spin_1s_linear_infinite_reverse]` (direction still INSIDE the shorthand; `size-3.5`,
   `motion-reduce:[animation:none]`, no inline `style`). The ring's 1s/linear arc transition also
   stays deliberate: our `stroke-dashoffset` rebinds once per second, the tracker's source ticks
   every 100ms (hence its shorter tween).
4. **Deliberate divergence:** the inline **"Refreshing in Ns"** text stays — the tracker shows its
   seconds on hover only; here the countdown is stated at a glance (explicit user requirement).

🔴 **Supersedes** any round-2c text that described an **unsized** ring (the round-2c entry above
says only "`-rotate-90` SVG ring" / "1s linear transition", which is still true — but any reading of
it as a full-size donut is wrong: the round-2c render was 112×112px). It also supersedes the
round-2c/earlier **3s** spinner wording: the shorthand is `spin_1s` now. Geometry, arc colour,
drain/clamp rule, state machine, tooltip and testids are otherwise unchanged.

**Evidence:** full suite **131 files / 1786 tests passed**, `npm run build` green, `prettier`
clean; live in the browser the ring measures **22×22 inside a 28×28 (`size-7`) slot, button
140×28** (was a 112×112 ring / 112×136 button); a click → 14×14 spinner → **"Updated" at 277ms** →
