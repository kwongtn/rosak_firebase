# 2026-10-03

## home: the network board, Phase 0 — foundations and quick wins

The plan is a five-phase rebuild of `/` as a live network board. Phase 0 lays the groundwork every
later phase reads — reader preferences, a URL-state seam, a pure summary rule, a hero, a real action
hierarchy on the card, and a board ordered worst-first — **without adding a single network read**.

1. **`PreferencesService` (`core/preferences/preferences.service.ts`).** Reader-owned display state
   (`pinnedLineIds`, `viewMode`, `density`, `lastReportedLineId`, `recentLineIds`) under the
   **versioned** key `rosak:preferences:v1`. API: `isPinned` / `togglePin` / `setViewMode` /
   `setDensity` / `setLastReportedLine` / `pushRecentLine` (deduped, capped at 5) / `reset()` /
   `snapshot()` / `hydrated()`. 🔴 **The constructor never reads storage.** It builds on the defaults
   and hydrates in `afterNextRender`, which does not run on the server — a constructor read would make
   the client's first paint disagree with the server's HTML and throw an `NG0500` hydration mismatch
   for any rider who had pinned anything. The persist `effect` is gated on `hydrated()` for the
   mirror-image reason: an ungated effect fires on its first run, BEFORE the read, and would overwrite
   real preferences with the defaults they are about to inherit. Every stored field validates
   **independently**, because a half-recognisable payload (an older deploy wrote fewer keys) is the
   common case, not an edge case — dropping the whole object would silently unpin a rider's lines
   because one unrelated key changed shape.
2. **`query-param.util.ts` (`core/url-state/`).** The read/write seam for URL-owned view state
   (`?view=`, `?sort=`, `?line=`, `?q=`), split exactly like `line-overview.page.ts`'s existing pattern:
   pure parsing over a `ParamMap`-shaped record (`parseEnumQueryParam`, `parseTextQueryParam`,
   `readEnumQueryParam`, `readTextQueryParam`), plus one browser-gated `navigate()`
   (`writeQueryParams`). Two rules callers now inherit instead of re-deriving: **a default value never
   appears in the URL** (`queryParamForWrite` → `null`) and **writes merge and replace, never push**.
   `isBrowser` is a parameter because reading `PLATFORM_ID` needs an injection context a plain
   function should not have — and because a _reactive_ `navigate()` during SSR hangs the render.
3. **`network-summary.util.ts`.** The board's whole rule, pure and total: `LINE_STATUS_SEVERITY_RANK`,
   `NEEDS_ATTENTION_PASSENGER_RANK`, `lineNeedsAttention`, `compareLineSeverity`,
   `sortLinesBySeverity`, `summarizeNetwork`, `networkHeadline`, `lineCallout`. Two decisions worth
   recording. First, the operational order is a **total order, not the backend enum's**:
   `TOTAL_DISRUPTION` 6 > `PARTIAL_DISRUPTION` 5 > `PARTIAL_ACTIVE` 4 > `DEFUNCT` 3 > `TESTING` 2 >
   `ACTIVE` 0 — DEFUNCT and TESTING are settled, un-actionable facts and must not outrank a line that
   is only partly running. Second, the passenger threshold is `DELAYED` (5), **not** `CROWDED`:
   crowding describes one carriage rather than the service, and counting it would leave the headline
   reading "0 of 16 lines running normally" on any busy evening. `PASSENGER_SEVERITY_RANK` (added to
   `passenger-status.util.ts`) mirrors the backend `PassengerStatus` enum order — the schema exposes
   the enum in declaration order, so a higher rank IS a more severe status, and the numbers are the
   server's order made numeric rather than an editorial layer on top of it.
4. **`app-home-hero`.** A full-width strip ABOVE the `home-panels` grid (the headline and tiles
   describe both columns, so a one-column hero would make half the summary lie): plain-language
   headline + an `app-info-popover` reading `metricDoc("network.lines-normal")`, the worst-line
   callout, four stat tiles, and an intent-based CTA row — Report a delay · Spot a train · Share a
   link · Live map. It **reads nothing**: `lines` / `linksToday` are bound from `store.lines()` and
   `store.feedTotalCount()`, both already in flight. "Report a delay" emits `reportDelay`, which the
   page answers by scrolling to the board; the chooser belongs to the board, not to a summary strip.
5. **Card CTA hierarchy + menu.** Two buttons, one primary and one secondary: **Report status**
   (`submit-line-status`) and **Log spotting** (`add-spotting-entry`) — same testids, de-jargoned
   copy. Pin and the two Line HQ links moved into a kebab (`line-card-menu` →
   `line-card-menu-panel`, items `line-card-pin` / `line-card-hq` / `line-card-hq-details`), closing
   on Escape / outside click / item choice. `src/app/ui/` has no dropdown primitive to reuse, so the
   menu is inline against the contract `app-info-popover` already established. The card also draws the
   line's `displayColor` as a leading accent rail and records the line into
   `PreferencesService.recentLineIds` on the expanded panel's open edge.
6. **The board is now ONE worst-first list.** The ACTIVE-first partition with a collapsed
   "Other lines" `<details>` is **gone** (testids `other-lines` / `other-lines-summary` retired). It
   had the right instinct — a degraded line must not read as routine — and the wrong mechanism: the
   page's own hero would say "3 lines need attention" above a column of lines that are fine, and the
   fold also inverted the priority it was meant to protect (a rider scanning for a problem read the
   healthy majority first). Rows are `sortLinesBySeverity(lines())` under a
   `line-board-attention-heading` caption counting with the hero's OWN predicate, so the caption, the
   hero tile and the row order cannot disagree.
7. **Smaller things.** The `""` route gained `title: "MLPTF | Live Network Board"` (the one route
   without a title) and `HomePage` sets the `<meta name="description">` through `Meta.updateTag`, so
   it lands in the SSR HTML. The `feed-empty` block became an invitation — "No links yet today — be
   the first" plus a `feed-empty-cta` that opens the same shared sheet the hero's "Share a link" does,
   because the old copy stated a fact and left the reader to work out what to do about it, which is
   how a page whose job is community reports ends up reporting nothing.
8. **Methodology registry.** Three `MetricDoc`s (`network.lines-normal`, `network.needs-attention`,
   `network.severity-order`) plus the `NEEDS_ATTENTION_PASSENGER_RANK` constant, with the `line-status`
   section's `lastReviewed` bumped to 2026-10-03. The hero surfaces the headline metric through the
   popover, so the number in the tile and the sentence on `/methodology` cannot drift.
9. **`--brand`.** Brand orange (`#ee7104`) as an **accent only** — never an action control's fill
   (`--primary` stays the blue). Added to `:root` and `:root.dark` and mapped through
   `@theme inline { --color-brand: var(--brand) }`, so `bg-brand` compiles to `var(--brand)` and the
   dark override is picked up with no `dark:` utility to drift. The hero's rail and its primary CTA are
   the only surfaces using it today.
10. **`@ng-icons/lucide` works on Angular 22** (installed v34, peer `@angular/core >=21`). This is
    the library's first usage in `src/` — `NgIcon` + `provideIcons({ lucideEllipsisVertical,
lucidePin, lucideExternalLink })` builds, tests and SSR-bundles clean, so **no inline-SVG
    fallback was needed**. The existing chevron SVGs are untouched.
