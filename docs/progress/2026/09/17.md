## About page: admin editor + search + chronological project sort

- **What**: `/about` enhanced with three changes:
  - **Admin editor**: admins get an "Edit" button (visible only when logged in with the `admin`
    claim). Clicking it opens a structured in-page form for the entire `public/about` Firestore
    doc (aboutProject, projects, personnel incl. nested socials, techStacks — add/remove/edit all
    fields). Edits are held in a normalized signal-based draft (`draftFromDoc()`); nothing touches
    Firestore until the admin clicks **Save**, which calls `setDoc()` via `sanitizeDraft()` to
    guarantee no `undefined` values (Firestore rejects them) and strips empty nameless placeholders.
    Cancel discards the draft. The live `onSnapshot` subscription re-renders the page automatically
    on save.
  - **Search/filter**: a search box filters projects, personnel, and tech stacks by name/description
    (case-insensitive).
  - **Chronological project sort**: projects are now sorted ascending by `startDate`, giving a
    loose timeline (entries without a date fall to the end).
- **New files**: `data/about-edit.util.ts` (pure `draftFromDoc`, `sanitizeDraft`, `emptyProject`,
  `emptyPersonnel`, `emptyTechStack`, `emptySocial`, `filterAndSortProjects`, `filterPersonnel`,
  `filterTechStacks`) + `data/about-edit.util.spec.ts` (13 Vitest cases covering draft
  normalization, sanitization/filtering, and sort order).
- **Gates**: vitest 60 files / 460 tests green (incl. new specs), `npm run build` passes,
  prettier clean.

## Insiden: month-window server-side incident fetching

- **What**: `/insiden` no longer fetches every incident on load. `InsidenPage` now sends the
  backend `calendarIncidents(filters:)` a window of the selected month ±14 days OR unresolved
  incidents (`OR: { ongoing: true }`) so the pinned section keeps working; the window reloads
  when the viewed month changes and is reused for day clicks inside the same month
  (`calendarMonthRange()` in `calendar-date.util.ts`). The situasi tab's unfiltered copy of the
  query is untouched.
- **Backend**: `CalendarIncidentFilter.date` range previously excluded incidents ending before
  the window start / starting after it — replaced the day-anchored branches with one inclusive
  overlap `Q` (start ≤ window end AND (end ≥ window start OR ongoing)); covered by two new tests
  in `incident/tests.py`.
- **Calendar**: year picker no longer derives options from loaded rows (a single month's data
  can't reveal history); floors at the app's 2022 launch and includes the viewed year.
- **Gates**: vitest 59 files / 453 tests green (incl. new `insiden.page.spec.ts` window-reload
  specs + `calendar-date.util.spec.ts` range cases), `npm run build` passes, prettier clean.
  Backend: `ruff check` clean, 9/9 `TestCalendarIncidentFilter` pass. Full backend suite has
  9 pre-existing environment failures (Firebase creds dir, `VehicleStatus.NOT_IN_SERVICE`,
  telegram) verified present on a clean stash — unrelated to this change.
