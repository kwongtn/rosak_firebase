## Fix: the Pending pill and the pending group now key off the approval status

- **Defect** (reproduced in a browser): approved community links rendered the "Pending" pill
  (`title="Awaiting admin approval"`) — every card on the home feed (whose query only ever returns
  approved links) and four approved links under `/spotting/:lineId/details/situasi`'s
  "Pending (4)".
- **Root cause**: the UI conflated the two independent link axes. `SocialMediaLink.status`
  (`LIVE`/`PENDING_APPROVAL`) is the approval axis — the submit service overrides the model's
  `PENDING_APPROVAL` default for admin actors — while `completed` is the admin console's separate
  "mark handled" boolean (the console's own `completed` filter). The demo seeder writes `status=LIVE`
  and never sets `completed`, so every seeded link rendered as pending: `LinkCardComponent` gated the
  pill on `!completed`, `LinkListComponent` split approved/pending on `completed`, and `FEED_QUERY`
  selected `completed` but not `status`, so the home card could not see the approval axis at all.
- **Fix** (`be72cad`): `FEED_QUERY` now selects `status` and `FeedLink` carries it; the shared
  `LinkCardItem` gained `status?: string | null` (kept deliberately wide so both source nodes stay
  structural — `FeedLink.status` is the `SocialMediaLinkStatus` union, `PublicSocialMediaLink.status`
  is `string | null`; no casts) and its `completed` doc comment now describes the separate handled
  flag instead of claiming it drives the pill. `LinkCardComponent` renders `link-pending` only for
  `status === "PENDING_APPROVAL"`; `LinkListComponent` partitions approved =
  `status !== "PENDING_APPROVAL"`, pending = `status === "PENDING_APPROVAL"`. `completed` is
  untouched as the console's own axis; `canEditLink`, the vote control, the URL/favicon rendering,
  the time tooltip and the footer are unchanged.
- **Tests**: `link-card.component.spec.ts` pins all three cases — `PENDING_APPROVAL` shows the pill
  with its exact title, `LIVE` shows none even with `completed: false` (and with `completed` absent —
  the regression), and `completed: true` on a `PENDING_APPROVAL` link still shows it (the axes are
  independent). `links-section.component.spec.ts` asserts a `LIVE` link lands in the approved
  day-grouped list (outside the pending collapsible) and a `PENDING_APPROVAL` link lands in the
  collapsed "Pending (1)". `home.page.spec.ts` asserts a `LIVE` feed card (with `completed: false`)
  renders no pill; every `FeedLink` fixture gained `status: "LIVE"`. e2e `home.spec.ts`'s feed node
  is now `status: "LIVE"` + `completed: false` with the pill assertion driven by the approval axis.
- **Docs**: `insiden.md` (card pill + list grouping) and `home.md` (feed node selection + card pill)
  corrected; `MISTAKES.md` entry added.
- **Gates**: unit suite and e2e results recorded in the task report.
