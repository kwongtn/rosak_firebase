## SSR: home status chips restored after the NG0502 projection trap (f0954ac)

- **What**: `GET /` had been serving HTTP 200 with a 22-byte `Internal server error.` body (dev
  `:4200` and the prod SSR build) since `5c53c4c`; `/methodology` was unaffected. The error was
  swallowed by `@angular/ssr`'s `writeResponseToNodeResponse` bare stream catch
  (`node_modules/@angular/ssr/fesm2022/node.mjs:401-404`), so nothing was logged. Instrumenting the
  response stream exposed `NG0502: During serialization, Angular was unable to find an element in
the DOM: … #node(projection) <div popoverExtra=""> …` at
  `calcPathForNode`/`appendSerializedNodePath`/`annotateForHydration`. Root cause:
  `StatusInfoChipComponent` projects `<div popoverExtra>` into the shared `InfoPopover`'s
  `<ng-content select="[popoverExtra]" />`, which sits inside `@if (_open())` — false on the server,
  so the projected node is orphaned with no DOM counterpart and the hydration serializer throws
  mid-stream. `ngSkipHydration: ""` on the `InfoPopover` host
  (`src/app/ui/info-popover/info-popover.ts:45`) is Angular's documented remedy for
  hydration-incompatible content, and every future `[popoverExtra]` consumer (e.g. the planned
  provenance chip) is covered. Consequence: Angular's `clearElementContents` discards the host's
  children and re-renders the component, so `app-info-popover` instances re-render on hydration
  instead of hydrating — the server markup inside `app-info-popover` is newly created client-side
  (functionally identical; a11y and the public API are unchanged).
- **Tests**: new `src/app/features/home/line-pulse/status-info-chip.server.spec.ts` renders the real
  chip through the actual server path (`renderApplication` + `provideClientHydration`) and fails with
  the same `NG0502` without the fix. Full suite **86 files / 744 tests** green; `npx prettier --check
.` clean; `npm run build` exit 0; dev `/` 243,501 bytes (markers `passenger-status`,
  `line-vehicle-count`, `line-status-badge` and info triggers present) and `/methodology` 44,346;
  prod SSR `/` 264,232 and `/methodology` 66,226.
- **Docs**: `MISTAKES.md` entry for the conditional-slot projection trap;
  `docs/components/methodology.md` popover SSR note; `docs/components/home.md` chip + server-spec
  line; this entry.

## Popover: one panel at a time + a 300 ms hover grace (53255b4, this change)

- **What**: two behaviour changes to the shared `app-info-popover`.
  - **Exclusivity** (`InfoPopoverRegistry`, `providedIn: "root"`, same file): the registry holds the
    currently-open popover. Every open path (hover, focus, click, tap) claims the slot — closing
    whichever instance held it and cancelling that instance's pending close timer — and every close
    path (delay timer, Escape, outside click, blur-leaves-host, tap-toggle-close) releases it;
    `DestroyRef.onDestroy` releases too, so a destroyed component never lingers as the active one.
    Fixes the overlap: moving the cursor from pill A to pill B used to leave A's panel open for the
    whole grace window while B's panel opened. The registry is injector-scoped rather than
    module-level because the non-isolated test runner and SSR both share module state.
  - **Grace window**: `HOVER_CLOSE_DELAY_MS` 1000 → **300 ms** — still long enough for the pointer to
    cross the few pixels between a pill and its own panel (the reason the delay is not 0), short
    enough that pill-to-pill movement feels immediate.
  - The panel's `absolute … z-20` stacking is untouched: while the cursor is over A's open panel,
    hit-testing lands on the panel, so the pills it overlays never fire `mouseenter` and stay closed.
  - Every other semantic is unchanged: the hover-capable probe, focus-opens/blur-closes only when
    focus leaves the host, click never closes while hovering, tap toggles on touch, Escape closes and
    returns focus to the trigger, SSR renders closed and inert, `showIcon`/`showMethodologyLink`.
- **Tests**: `info-popover.spec.ts` re-pins the delay at 300 ms (fake-timer boundaries) and adds the
  two-popover exclusivity test — A opens on hover, hovering B closes A (`aria-expanded="false"`,
  panel gone) while B opens — plus a stacking pin (`absolute` + `z-20`) for the hit-testing
  mechanism. RED first (2 failing) → GREEN; full suite **86 files / 755 tests** green;
  `npx prettier --check .` clean; `npm run build` exit 0.
- **Docs**: `docs/components/methodology.md` hover bullet now states the 300 ms grace and the
  one-panel-at-a-time rule; this entry and the monthly row.

## spotting/line-details: vehicle-spotting-grid mobile stacked layout below 768px (this change)

- **What**: the `/spotting/:lineId/details` "Spotting Activity" vehicle × date grid
  (`line-details/vehicle-spotting-grid/vehicle-spotting-grid.component.ts`) gained a mobile layout
  below 768px (Tailwind `md`); desktop (>=768px) is unchanged.
  - Each vehicle renders as a full-width NAME row directly above its own horizontally-scrolling
    date row; each vehicle type renders a full-width TYPE LABEL row directly above its per-date
    totals row.
  - Vehicle names and type labels pin left while the dates scroll: an inner
    `<div class="sticky left-0">` inside a full-width `colspan` `<td>` (never `sticky` on the `<td>`
    itself, table-cell colspan sticky is unreliable). The current type label and its totals stay
    pinned under the month/day header via a page-sticky 2-row overlay that is a sibling of the
    `overflow-x-auto` body (never inside it; `position: sticky` is inert inside a
    non-vertically-scrolling overflow ancestor).
  - Layout switches on an `isNarrow` signal initialised synchronously from
    `window.matchMedia("(min-width: 768px)")` (inverted), kept live by a `change` listener torn
    down in `DestroyRef`.
  - The component gained `host: { ngSkipHydration: "" }`: SSR renders the desktop grid with real
    data (`REQUESTS_CONTRIBUTE_TO_STABILITY` defaults `true`, so the GraphQL POST is a pending task
    the server awaits), so a viewport-conditional `@if` would mismatch hydration on mobile;
    skipping hydration is the documented remedy (same as `ui/info-popover/info-popover.ts`).
  - Scroll math: `pinnedH = isNarrow() ? 2*ROW_H : ROW_H` drives the section-handoff push; there is
    deliberately no mobile last-section clamp because the overlay is the only pinned element there
    (its own native sticky release plus `pastGrid` handle the end of the grid).
- **Why**: the desktop three-way split (fixed names table + mirrored header + `overflow-x-auto`
  body) cannot shrink to a ~390px viewport without a ~900px horizontal scroll; the stacked layout
  puts each name/type beside its own dates so the grid stays usable on a phone without a nested
  vertical scroll region.
