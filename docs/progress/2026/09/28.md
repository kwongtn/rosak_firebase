# 2026-09-28

## feed + console: Official badge for ingested posts, HIDDEN status wired through the UI

Backend half already landed (`rosak_backend` `0d2eea2` — "hide links from the public feed and
expose isAutomated", plus `e099157`); this is the frontend half of that contract.

- **What**: three changes on top of the existing link surfaces.
  1. `SocialMediaLinkStatus` gained `"HIDDEN"` (`home.queries.ts`, the single copy of the union —
     the console row type and the `SocialMediaLinkInput.status` tri-state already reference it).
     `linkStatusLabel` maps it to **Hidden**, and a new `linkStatusVariant` gives it the muted
     `neutral` chip so a moderated-away submission never renders like the solid `default` chip of
     a published one (the profile `mine` list is the only public-facing surface that can see a
     HIDDEN row at all — the public feed never returns it).
  2. The shared `app-link-card` renders an **Official** chip (`hlmBadge variant="info"`,
     `data-testid="link-official"`, `title="Captured automatically from an official operator
account"`) in its tag row when the link's new `isAutomated` is true. `FEED_QUERY` now selects
     `isAutomated` and `FeedLink`/`LinkCardItem` carry it (optional on the card contract, since
     the insiden links tab and situasi don't select it yet and must simply show no chip).
  3. `/console/insiden/links` gains a **Hide** row action for every row that isn't already
     `HIDDEN`, sending the same `UPDATE_SOCIAL_MEDIA_LINK_MUTATION` with `status: "HIDDEN"` and
     reloading through the existing `fetchLinks()`; **Approve** stays on every non-`LIVE` row, so
     un-hiding is just Approve. Each row also shows an **Official** chip under the submitter when
     `isAutomated` is true, so an admin can tell an ingested row from a community submission
     without opening the panel.
- **Contract note (unchanged trap)**: `SocialMediaLinkInput` is still replace-not-patch, so the
  payload builder moved into a pure util — `console/insiden/data/link-status-input.util.ts`
  (`linkStatusInput(link, status)`) — now shared by Approve and Hide instead of duplicated. A
  status-only input would still blank the title and strip all four M2M tag sets. The
  `linkStatusInput` doc comment says so at the type; the shape is pinned by its own spec.
- **Verified**: 4 new specs in `console/insiden/links` (Hide only on non-HIDDEN rows while
  Approve stays on a hidden one; the click sends the full payload with `status: "HIDDEN"` and the
  right id; the list reloads and the row comes back `HIDDEN` with the success toast; a failed
  mutation toasts and leaves the list untouched), one for the un-hide path (Approve on a HIDDEN
  row sends `status: "LIVE"`), one for the Official chip (ingested row badged, community row not),
  4 for `linkStatusInput`, 1 for the card chip (hidden when the field is absent or false) and 3 for
  the HIDDEN label/variant util. Mutation-checked: inverting the Hide guard + dropping
  `categoryIds` from `linkStatusInput` turned 5 specs red (819 → 814 passed); weakening the card
  guard to `!== undefined` and removing the HIDDEN label/variant branches turned 3 red (819 →
  816). Full suite `npm test -- --no-watch`: **94 test files / 819 tests passed**.
  `npx prettier --check .` clean; `npm run build` exit 0 (the `src/styles.css:2737`
  css-syntax-error warning and the `gtfs-realtime-bindings` CommonJS warning are pre-existing).
- **Docs**: this entry + the monthly `SUMMARY.md` row and the yearly `SUMMARY.md` home/console
  rows + `docs/components/home.md` (feed query contract + the card's chip) and
  `docs/components/insiden.md` (the shared card's `link-official` test id and the new contract
  field). `docs/components/console.md` still covers only the spotting moderation page, so there
  was no opportunity/TODO item to remove. No new `MISTAKES.md` entry — the replace-not-patch trap
  is already catalogued and this change reuses its existing fix.

## about: Admin editor cards flow in the public display grid

- **What**: `/about`'s admin editor rendered every `projects` / `personnel` / `techStacks` entry as
  a full-width stacked card, while the public sections below lay their cards out in
  `grid grid-cols-1 gap-3 sm:grid-cols-2 lg:grid-cols-3`. Each editor `@for` is now wrapped in that
  same grid, so an edit cell sits where its rendered card will: 1 per row on mobile, 2 at `sm`,
  3 at `lg`. The socials row inside a personnel cell and the tech-stack name row also gained
  `flex-wrap`, so those inputs wrap within a one-third-width cell instead of squeezing the
  URL/name input against their Remove button.
- **Why**: the editor sits directly above the content it edits, but the two layouts disagreed — at
  desktop widths the admin saw one wide input card per person while the page showed three cards per
  row, making it hard to eyeball which edit cell maps to which displayed card.
- **Verified**: `npx prettier --check .` clean; `npm test -- --no-watch`: **94 test files / 819
  tests passed**; `npm run build` exit 0. No new spec: this is a template-only class change with no
  logic to unit-test (the editor's pure helpers stay covered by `about-edit.util.spec.ts`), and the
  page's first spec would need new Firestore mocking infrastructure for a class-attribute
  assertion.
- **Docs**: this entry + a monthly `SUMMARY.md` row. `docs/components/about.md` gained a line in
  its editor bullet describing the mirrored grid. No opportunity/TODO item there covered editor
  layout, so nothing was removed; no new `MISTAKES.md` entry.
