## Follow-up: hermetic reporter + step gates (same day)

Two issues survived the first push:

- `image-upload.service.spec` still failed only in CI. Root cause is structural: the
  builder runs Vitest with `isolate: false`, so workers share one module registry and
  whichever spec evaluates the service first decides its `Sentry` binding — the spec's
  `vi.mock` assertion could never pass once another file bound it to the real module.
  Fixed with an injectable `UPLOAD_ERROR_REPORTER` token (root factory still Sentry);
  specs spy via TestBed DI. Lesson recorded in `MISTAKES.md`.
- The job-level `if:` on `secrets` was rejected by GitHub's validator (0s startup
  failure). Replaced with job `env` presence flag + step-level gates, so
  install/build/test still run every push while auth/deploy skip until the WIF secrets
  (`WIF_PROVIDER`, `GCP_SA_FB_FUNCTIONS`) are created — that GCP/repo-settings step
  remains manual. `actionlint` (installed) now gates workflow edits.
- Result: `CI` (lint/test/build) and `Deploy Functions` both **success**.
