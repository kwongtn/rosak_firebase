# 2026-09-26

## console/links: Approve action for the social-media link queue (OFFICIAL_POST_INGESTION.md §5.3, this change)

- **What**: `/console/insiden/links` gained an admin **Approve** row action, rendered only while the
  row's approval `status` isn't `LIVE`. `SOCIAL_MEDIA_LINKS_QUERY` now selects `status` and
  `SocialMediaLinkRow` carries it (`SocialMediaLinkStatus`, the union already declared in
  `home.queries.ts` — no third copy). `approveLink()` sends the existing
  `UPDATE_SOCIAL_MEDIA_LINK_MUTATION` with `status: "LIVE"`, then calls the component's private
  `fetchLinks()` refresh (the same mechanism `markCompleted` uses — no route reload). Errors go to
  `ToastService.error`; nothing is swallowed. The Approve button sits in the row Actions column
  ahead of "Mark completed" and calls `$event.stopPropagation()` so it never opens the edit sheet.
  No filters, badges or bulk actions (spec §8 defers those).
- **Why**: the queue is where the auto-ingested operator posts surface, and the spec makes approval
  the publish gate. Until now an admin could edit a pending row (which lands it live as a side
  effect of any admin edit) or mark it completed, but there was no explicit approve verb — and the
  queue query did not even select `status`, so the UI could not tell a pending row from a live one.
- **Contract note**: `SocialMediaLinkInput` is not a patch. `url` is non-nullable and the backend
  service assigns `title` and calls `.set()` on the four M2M tag relations unconditionally, so the
  approve payload re-sends the row's current `url`/`title` and all four id lists next to
  `status: "LIVE"`. A status-only input would blank the title and strip every tag. Recorded in
  `MISTAKES.md`; the `UpdateSocialMediaLinkVars` doc comment now says so at the type.
- **Verified**: 4 new specs (Approve only on non-`LIVE` rows; the click sends
  `socialMediaLinkId` + the full `status: "LIVE"` payload and leaves the sheet closed; the list
  reloads and the row comes back `LIVE`; a failed mutation toasts and leaves the list untouched).
  Mutation-checked: inverting the `@if` guard and dropping `categoryIds` from the payload turned 3
  of them red (24 → 21 passed). Full suite `npm test -- --no-watch`: **93 test files / 805 tests
  passed**. `npx prettier --check .` clean; `npm run build` exit 0.
- **Docs**: this entry + the monthly `SUMMARY.md` row and the yearly `SUMMARY.md` console row +
  `MISTAKES.md`. No component-doc opportunity/TODO item covered this (the console component doc only
  covers the spotting moderation page, and `docs/components/insiden.md`'s opportunity list has no
  link-approval entry), so nothing was removed from a component doc.
