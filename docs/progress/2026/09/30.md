## home: quick submit box rework + advanced-input sheet prefill

- **What**: the home feed's submit box is now a two-mode quick form.
  1. `LinkSubmitBoxComponent` drops the line-status select, the lines multi-select and the local
     "status needs a line" guard. Logged in it renders the URL field plus two buttons in one
     responsive row (`flex-col` on mobile, `sm:flex-row` from `sm` up): **Submit Link**
     (`type=submit`) sends only `{ input: { url: normalizeFeedUrl(url) } }`; **Advanced Input**
     (`data-testid="advanced-input"`, `type=button`) calls
     `LinkSheetService.open(undefined, { url: trimmed || undefined })` to open the shared right-side
     link sheet in create mode with whatever is already typed. The inline `feed-submit-error` block
     moved inside the URL cell so the desktop row stays two columns.
  2. `LinkSheetService` gains a `prefillUrl` signal and a consume-once `takePrefillUrl()`, and
     `open(context?, prefill?)` takes an optional second `{ url? }` argument (trimmed; empty → null).
     `openEdit()`/`close()`/`setOpen(false)` all clear it, so edit mode never prefills and a reopen
     without a new `open(..., { url })` starts blank. Existing `open()` / `open(context)` call sites
     are unchanged.
  3. `LinkFormComponent` applies the prefill on a create-mode open inside the existing edit-hydration
     effect's `!target` branch (`_applyCreatePrefill()`); the read is wrapped in `untracked()` so
     nulling the service value is not a tracked dependency, and a `_prefillApplied` guard (reset when
     the sheet closes) prevents a late effect re-run from re-applying it.
- **Why**: the quick box should stay a one-field "paste a link" affordance, while the fuller form
  (title + asset tags) stays reachable without re-typing the URL — reusing the exact sheet every
  other surface already hosts rather than growing the home-local form.
- **Verified**: focused specs only during implementation, full suite at close-out — `npx prettier
--check .` clean; `npm test -- --no-watch`: **96 test files / 843 tests passed**; `npm run build`
  exit 0. New/changed specs: `link-submit-box.component.spec.ts` (two modes, advanced opens the
  sheet with the trimmed URL) and `link-sheet.service.spec.ts` (prefill set/consume-once/cleared by
  edit/close) plus `link-form.component.spec.ts` (create-open prefill applied once, never in edit
  mode). Commit `abd0a79`.
- **Docs**: this entry + the monthly/yearly `SUMMARY.md` rows; `docs/components/home.md` (the
  two-mode quick form, the `Advanced Input` prefill, the dependency/extension notes) and
  `docs/components/insiden.md` (the `LinkSheetService` prefill API + the form's create-open prefill).

## home: collapsed Last Week link list with day-grouped Load More

- **What**: a collapsed **Last Week (N)** section below the unchanged today feed.
  1. `home.page.ts` renders a `last-week-toggle` button (`aria-expanded`, chevron rotate) reading
     `Last Week ({{ store.lastWeekTotalCount() }})`; `_lastWeekExpanded = signal(false)` keeps the
     panel unmounted until first expand. Expanded, it shows a skeleton (`last-week-skeleton`), an
     empty state (`last-week-empty`, "No links in the last week.") and the day-grouped links
     (`last-week-day-group`, headings Today / Yesterday / `EEE, d MMM`) through the shared
     `app-link-card`, with its own `last-week-load-more` button gated by
     `canLoadMoreLastWeek` (next page exists and nothing in flight).
  2. `HomeStore` gains a third `graphqlResource` (`lastWeekResource`, static vars `first:
LAST_WEEK_PAGE_SIZE` (20), `status: "LIVE"`, `lastWeekOnly: true`, `alignPageToDay: true`) and
     an appended-pagination mirror (`lastWeekAppended*`/`lastWeekNextCursor`/`lastWeekLoadingMore`)
     driven by `loadMoreLastWeek()`. Derived: `lastWeekLinks`, `lastWeekPageInfo`,
     `lastWeekTotalCount`, `lastWeekDayGroups` and `isLoadingLastWeek`. `reloadAll()` resets both
     appended-page sets and reloads all three resources; `hasError()` ORs in the last-week resource.
  3. The authenticated `userVote` overlay now issues **two** reads in `Promise.all` (today feed first
     page + last-week first page) and merges every non-zero vote into the one `userVotes` map.
  4. `home.queries.ts` gains `$lastWeekOnly`/`$alignPageToDay` on `FEED_QUERY` and the matching
     optional `FeedQueryVars` fields; the today feed's variables are byte-for-byte unchanged.
  5. New pure `feed-day-groups.util.ts` (`groupFeedLinksByDay(links, now?)`) buckets the resident
     links into local-calendar days (LOCAL, not UTC — the backend's `created` values are naive
     Asia/Kuala_Lumpur) with `Today`/`Yesterday`/`EEE, d MMM` labels, merging interleaved same-day
     rows and dropping empty days; a malformed date falls into a headerless `""` group.
- **Why**: the community wants to see recent-but-not-today activity without scrolling a
  service-day-scoped feed; the window is computed backend-side (`lastWeekOnly`) so no date is ever
  baked into query variables (SSR TransferState needs identical vars), and `alignPageToDay` keeps a
  day's group whole across the 20-link Load More boundary.
