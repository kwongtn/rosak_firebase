# 2026-09-23

## Home: two-panel front page + 30s line-refresh countdown (commit `feat(home): split the front page into two panels with a line-refresh countdown`)

- **What**: the community front page is now split for desktop and the line data refreshes on a
  visible 30s beat.
  - **Two panels** (`home.page.ts`): the submit box, retry banner and `<app-footer />` stay full
    width; only the feed and the line-status sections moved into a responsive wrapper
    (`data-testid="home-panels"`, `flex flex-col gap-6 lg:grid lg:grid-cols-2 lg:items-start`) —
    stacked on mobile, two columns from `lg` up, URL feed LEFT and line statuses RIGHT (DOM order
    unchanged, so the submit → feed → lines ordering assertions still hold).
  - **Feed full height** (`home.page.ts`): the `feed-scroll` container lost both
    `max-h-[60vh]` and `overflow-y-auto` and renders every loaded link — the client-side reveal
    cap (`FEED_INITIAL_VISIBLE`, `visibleCount`, `visibleFeedLinks()`) was deleted. There is no
    inner scroll any more: the page itself scrolls, and `feed-count` now reports
    `store.feedLinks().length` against `store.feedTotalCount()`. Load More still pulls the next
    page (`FEED_PAGE_SIZE = 8` unchanged), and hides while a page is in flight.
  - **Lines-only polling** (`home.store.ts`): `polling` is public now (the page renders its
    countdown) and its callback is the new `reloadLines()` — `linesResource.reload()` plus a
    `linesRefreshTick` bump — instead of `reloadAll()`. The beat therefore never touches the
    feed, so a poll can't wipe the user's appended Load More pages; `reloadAll()` is unchanged
    for the submit/edit flows. `start()`/`stop()` keep the existing 30s lifecycle.
  - **Countdown** (`home.page.ts`): a row at the top of the line panel
    (`data-testid="line-refresh-countdown"`) with the spinner SVG, `Refreshing in {{ … }}s`
    (`HomeStore.polling.secondsRemaining()`) and a `Refresh now` button
    (`data-testid="line-refresh-now"`) wired to `polling.refreshNow()`. No interval select —
    the cadence is deliberately fixed at 30s (mirrors situasi-section minus its picker).
  - **Accordion refresh** (`line-pulse-list.component.ts` / `line-pulse-card.component.ts`):
    both gained `refreshTick = input(0)`; the page feeds the store's tick into the list, the list
    into every card (active and "Other lines"), and the card into the expanded panel's
    `app-line-status-chart` / `app-line-status-reports` — whose existing applied-tick effect
    re-reads their own resource while open. Feeding stops there: the two leaf components were
    not modified.
- **Tests**: `home.store.spec.ts` pins the poll callback as lines-only (tick bumps, lines
  re-requested, `httpMock.expectNone`ed feed, appended pages + cursor survive) and that
  `reloadAll()` still resets the appended pages without bumping the tick. `home.page.spec.ts`
  asserts all loaded links render, the `lg` two-column wrapper with feed-first child order, the
  uncapped feed container, the countdown text/button, and the tick handed to the list; its
  `StoreMock` gained `polling` + `linesRefreshTick`. List/card specs pin tick forwarding.
  Scoped vitest: 4 files / 51 tests green; `npx prettier --check .` clean.
- **e2e**: `e2e/home.spec.ts`'s stale "under the scroller" comment corrected; its
  `feed-count` (`Showing 1 of 9`), `feed-load-more` and `other-lines` selectors are unaffected by
  the restructure (same rendered content, new container).
- **Docs**: `home.md` updated (layout, polling bullet, `refreshTick` inputs, extension points).

## Spotting: a cleared combobox / station select really deselects (commit `1f37d7d`)

- **What**: emptying a shared `HlmCombobox` now clears the selected value instead of snapping the
  old label back on blur. The control gained an `emptyValue` input (default `undefined`);
  `_onInput` writes it when the text is emptied, and `_syncSearchToValue` short-circuits on
  `undefined` so it can no longer resurrect a cleared field. The report form's line and vehicle
  pickers bind `emptyValue=""` (string-typed Signal Forms fields must, because Signal Forms drops a
  node whose model becomes `undefined` while its control is rendered), and the three station
  `<select>` placeholder options lost `disabled`, so picking `Select a station` clears the station.
- **Why**: the typed text and the committed value are separate states in a combobox; clearing the
  text never cleared the `[formField]`-bound `value`, so the field looked cleared but kept
  submitting the old id.
- **Tests**: `ui/combobox/combobox.spec.ts` covers clear-on-empty (and non-empty mid-search) and
  `report-form.component.spec.ts` the placeholder-clear path; the three consumers (report-form,
  vehicle-detail, calendar) already guard falsy values.
- **Docs**: `spotting.md` form-state bullet + `MISTAKES.md` updated; this entry.
