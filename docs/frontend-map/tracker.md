## Purpose

Tracker is an experimental ("Alpha"-tagged), map-based live vehicle tracking view: a full-screen map overlaid with GPS positions from public Malaysian GTFS-realtime feeds (buses/rail), plus optional static GTFS stop markers and a static railway-line overlay. It is nominally aimed at `betaTester`-flagged users (it only appears in the nav for them), but because its route guard is commented out, it is reachable by any visitor, authenticated or not. It sits alongside `/situasi` as one of the app's two beta/experimental "Alpha" features, distinct from the core `/spotting` (TranSPOT) and `/insiden` product areas.

## Functionality & Behavior

**Map (`TrackerMapComponent`)**

- On init, hides page scroll (`document.documentElement.style.overflow = "hidden"`, `map.component.ts:120`) and restores it (`"auto"`) on destroy (`map.component.ts:192`) — this is the _only_ thing that resets scrolling; if `TrackerMapComponent` is ever destroyed without its `ngOnDestroy` running (e.g. hot-reload edge cases), the whole app would be stuck non-scrollable.
- Creates an `@antv/l7` `Scene` bound to `<div id="map">` (`map.component.html:1`, sized purely by `TrackerComponent`'s `nz-row`/`nz-col` layout — `map.component.scss` is empty, so the map/status-card side-by-side sizing comes entirely from `NzGridModule` columns in `tracker.component.html`), using the `@antv/l7` `Mapbox` map provider (`style: "normal"`, center `[101.492, 4.5]` — roughly central Peninsular Malaysia, zoom `6.5`, `token: environment.mapbox.token`). Scene construction runs `ngZone.runOutsideAngular` for performance (map redraws don't trigger Angular change detection).
- Loads two remote sprite images unconditionally into the scene (a marker dot and an arrow texture, both hot-linked from `gw.alipayobjects.com` CDN URLs, `map.component.ts:151-158`) — an external dependency outside the project's own asset pipeline.
- Adds a `PointLayer` shaped as `"marker"`, size 12 (`map.component.ts:160-161`) — **declared but nothing is ever fed into it as a data source**; `pointLayer` is never given `.source(...)`. Dead/unused layer as currently wired.
- Asynchronously fetches a static railway-line GeoJSON via `GetGeojsonService.getData("gs://rosak-7223b.appspot.com/public/malaysia_railway.geo.zip", "malaysia_railway.geo.json")` and renders it as an animated `LineLayer` (blue `rgb(22,119,255)`, animated flow texture using the arrow sprite, width 3, opacity 0.6) once loaded. This overlay is **always shown**, independent of the "Route layer" checkbox state in the status card (that checkbox toggles no map behavior at all — see Panel notes above).
- For every realtime feed the user activates (see Status Card), an `RtLayer` helper is created (`map.component.ts:140-149`, inside `ngZone.runOutsideAngular`) which:
    - Subscribes to that feed's `feedEntities` `BehaviorSubject<IFeedEntity>` on `GtfsRtStateService`.
    - On every emission, **removes and re-adds its entire `MarkerLayer`** (`processGtfs`, `map.component.ts:43-88`) — a full teardown/rebuild every refresh cycle (every ~30s by default) rather than incremental diffing.
    - For each vehicle entity with a `position`, creates (or reuses) a `Marker` at `{lng, lat}` and a `Popup` (anchor `"top"`) whose HTML is `Vehicle ID: <id></p><p>Trip ID: <tripId></p><p>Speed: <speed>` and title is `vehicle.label ?? "Vehicle label not found"`.
    - Preserves each popup's open/closed state across refreshes via an `isClosed` flag tracked through the popup's own `"show"`/`"hide"` events (`map.component.ts:66-72`) — so a user-opened popup for a given vehicle ID stays open across data refreshes, matched by vehicle ID as the stable key.
    - Entities without a `position` field are silently skipped (no marker, no error).
    - Torn down (`tearDown()`, unsubscribe + remove marker layer) when the corresponding source is deselected (`$deletedFeed`).

    - `applyLoading` exists on `StatusCardComponent` to drive the Apply button's spinner (`[nzLoading]="applyLoading"`) but is **never set to `true` anywhere** — the button never visibly shows a loading state even while `upsertSourceUrls` is doing async work.

- **Per-source progress indicator** (realtime panel only, `panel-rt-layer.component.html:17-54`): while a source's `isLoading` is true, shows a small spinner; once loaded, shows a circular progress ring (`nz-progress`, `nzType="circle"`, 20px, gradient stroke `#108ee9` → `#87d068`) whose percent is `RtGtfs.percentageTimeRemaining` (ticks every 120ms, computed as `(intervalMs - elapsedSinceLastUpdate) * 100 / intervalMs`) and a tooltip with seconds remaining (`RtGtfs.timeRemaining`, computed the same way but in seconds). **Confusing-but-currently-harmless expression**: the tooltip's number formatting is `((timeRemaining | async) ?? 0/1000 | number:'1.0-0')` (`panel-rt-layer.component.html:44-48`). Because Angular pipe/`??`/`/` precedence groups this as `(timeRemaining | async) ?? (0 / 1000)` — i.e. `?? 0` — the `/1000` never actually divides the live `timeRemaining` value; it only computes the _fallback_ used when the observable emits `null`/`undefined` (which it never does here, since `timeRemaining` is a `BehaviorSubject` seeded to `0`). The displayed number is therefore just the raw `timeRemaining` value, which happens to already be pre-converted to seconds inside `RtGtfs` (`gtfs-rt-state.service.ts:79-81`), so the tooltip currently shows a plausible seconds value — but the `/1000` reads as if it were converting ms→s at the template level, which it is not. A future edit that "cleans up" this expression by actually applying that division to the live value would silently break the displayed units (dividing an already-in-seconds number by 1000 again).
- The "Stops layer" panel (`panel.component.html:5-50`) shows the same list/spinner pattern but with no progress ring (static data has no refresh interval).
- Each checkbox row also has an info-icon link (`nz-icon` "info-circle") pointing at that source's human-readable documentation page (`checkbox.source`, e.g. `https://developer.data.gov.my/realtime-api/gtfs-realtime#ktmb`) — opens in the same tab (plain `<a href>`, no `target="_blank"`).
- `status-card.component.html:1` applies a CSS class combining a fixed `row-class` with `env.sentry.environment` (`"local" | "staging" | "production"`); `status-card.component.scss:5-7` only defines a `.staging` variant (extra top padding to clear a staging banner). No `.production`/`.local` override exists, so production and local render identically (base `padding-top: 70px`).

**Loading / empty / error states**

- No dedicated "empty" or "error" UI exists anywhere in this feature. If a realtime/static fetch fails (`gtfs-rt-state.service.ts:42-64`, `get-geojson.service.ts`), the error is only `console.log`'d/`console.error`'d — the UI keeps showing its last-known (possibly empty) state indefinitely, with no toast/banner/retry affordance.
- If the Firebase Storage rail-line GeoJSON fails to load, the `.then()` in `map.component.ts:163-188` simply never resolves/logs — no `.catch()` is attached, so a rejected promise here is an unhandled rejection.
- If a GTFS-static ZIP's `stops.txt`/`routes.txt`/`trips.txt` is missing/malformed, `Gtfs.fileParser` throws `Error("Issue with parser for ${fileName}")` (`gtfs-parser.ts:81-84`) after logging the underlying error; this rejects the `Promise.all` in `StaticGtfs.setZipInstance`'s handler chain with no `.catch()` either — `isLoading` would remain `true` forever for that source, so the panel spinner spins indefinitely.

## Data & API Contracts

**This feature makes no GraphQL calls at all.** A repository-wide grep of `/home/kwongtn/rosak_firebase/src/app/tracker/**` for `` gql` ``, `Apollo`, and `graphql` returns zero matches. It does not use the frontend's Apollo client (`src/app/graphql.module.ts`) and has no dependency on the Django/Strawberry backend at `rosak_backend` — **it does not map to the backend's `chartography` or `operation` GraphQL apps**, despite both existing on the backend and modeling superficially related concepts:

- `operation/models.py` defines `Line`, `Station`, `Vehicle`, `Asset`, etc. — static/admin-managed reference data (line names, station lists, fleet roster) surfaced through `operation/schema/schema.py`, consumed elsewhere in the frontend (e.g. Situasi/Console), but **not** by Tracker.
- `chartography/models.py` defines `Source`, `Snapshot`, `SourceCustomLine`, `LineVehicleStatusCountHistory` — periodic aggregate vehicle-status-count snapshots (a `trigger_line_vehicle_status_snapshot` admin-only mutation in `chartography/schema/schema.py:16-17`), not live per-vehicle GPS coordinates.

Neither app exposes anything resembling a live-vehicle-position feed or subscription today. Tracker instead sources its data from three places entirely outside the `rosak_backend` API surface:

1. **Public data.gov.my GTFS-realtime feeds** (real-time vehicle GPS positions), fetched directly client-side via `fetch()` in `GtfsRtStateService`/`RtGtfs.refreshGtfsData()` (`/home/kwongtn/rosak_firebase/src/app/tracker/services/gtfs-rt-state.service.ts:38-69`):
    - Endpoints are plain `https://api.data.gov.my/gtfs-realtime/vehicle-position/{agency}[?category=...]` URLs, hardcoded per-checkbox in `PanelSelectionService` (see table above). No auth headers, no API key.
    - Response body is a Protocol-Buffers `FeedMessage`, decoded client-side with the `gtfs-realtime-bindings` npm package (`transit_realtime.FeedMessage.decode(new Uint8Array(buffer))`). Consumed fields per vehicle entity: `entity.vehicle.vehicle.id` (used as the map key), `entity.vehicle.position.{longitude,latitude,speed}`, `entity.vehicle.vehicle.label`, `entity.vehicle.trip.tripId`. `entity.tripUpdate` is read only to `console.log` it — trip-update (ETA/delay) data is fetched implicitly (same feed) but never surfaced in the UI.
    - Polling: client-side `setInterval`, default **30000ms** (`RtGtfsConfig.intervalMs` default, `gtfs-rt-state.service.ts:29`), independently per source, started/stopped by checkbox selection — **not** a GraphQL subscription of any kind.
2. **Public data.gov.my GTFS-static feeds** (route/stop/trip reference data, ZIP of CSVs), fetched once (no polling) via Angular `HttpClient` in `GtfsStaticStateService.upsertSourceUrls` (`/home/kwongtn/rosak_firebase/src/app/tracker/services/gtfs-static-state.service.ts:89-104`) from `https://api.data.gov.my/gtfs-static/{agency}[?category=...]`, unzipped client-side with `jszip`, then each of `stops.txt`/`routes.txt`/`trips.txt`/`shapes.txt` is parsed with `csvtojson` inside `Gtfs` (`/home/kwongtn/rosak_firebase/src/app/tracker/map/gtfs-parser.ts`) into GeoJSON `FeatureCollection`s (points for stops, `MultiLineString` per route, `LineString` per trip/shape). As noted above, these parsed collections are computed but never rendered.
3. **Firebase Cloud Storage** (static asset, not Firestore): `GetGeojsonService.getData()` (`/home/kwongtn/rosak_firebase/src/app/tracker/services/get-geojson.service.ts`) resolves a `gs://rosak-7223b.appspot.com/public/malaysia_railway.geo.zip` reference via `@angular/fire/storage`'s `getDownloadURL(ref(storage, url))`, downloads it as an `arraybuffer` via `HttpClient`, unzips with `jszip`, and `JSON.parse`s the single file `malaysia_railway.geo.json` inside it into a GeoJSON `FeatureCollection` — this is the always-on blue rail-line overlay. No Firestore/Auth/Analytics SDK usage occurs anywhere in this feature.

**Browser storage**: none. No `localStorage`/`sessionStorage`/`IndexedDB` reads or writes anywhere under `tracker/**` — all panel selections, applied sources, and unsaved-changes state live only in in-memory service state for the lifetime of the page/tab and are lost on reload.

**Third-party/CDN dependency**: two sprite images (`marker`, `arrow`) are loaded directly from `gw.alipayobjects.com` (AntV's/Alipay's public CDN) at `map.component.ts:151-158` — not self-hosted, not versioned/pinned beyond the URL itself.

## State Management

Three Angular services, all `@Injectable({ providedIn: "root" })` — i.e. app-wide singletons, not scoped to the Tracker route/component tree, but in practice (confirmed by grep) only ever injected by Tracker's own components:

- **`PanelSelectionService`** (`/home/kwongtn/rosak_firebase/src/app/tracker/services/panel-selection.service.ts`) — holds the static `panels: IPanels` config object (the checkbox definitions/labels/endpoints/checked-state described above, hardcoded in the service, not fetched from anywhere) and `hasUnsavedChanges: BehaviorSubject<boolean>`. Populated at construction (module load) with hardcoded data; mutated only by `toggleChecked()` (flips a checkbox + sets `hasUnsavedChanges = true`) and `onApply()` (resets `hasUnsavedChanges = false`). Never reset/cleared — lives for the whole app session once instantiated (i.e., checkbox check-state and "Malaysia Railway" pre-check persist even if the user navigates away from `/tracker` and back, since it's a root singleton, not destroyed with the route).
- **`GtfsRtStateService`** (`/home/kwongtn/rosak_firebase/src/app/tracker/services/gtfs-rt-state.service.ts`) — holds `sources: { [key: string]: RtGtfs }` (one `RtGtfs` instance per active realtime feed, each with its own `feedEntities`/`percentageTimeRemaining`/`timeRemaining` `BehaviorSubject`s and its own `setInterval` polling loop) plus two `Subject`s, `$addedFeed`/`$deletedFeed`, used to notify `TrackerMapComponent` when to construct/tear down an `RtLayer`. Populated/mutated only via `upsertSourceUrls()` (called from `StatusCardComponent.onApply`). Intervals keep running (fetching every 30s) as long as a source stays in `sources` — they are only stopped when a checkbox is unchecked _and_ Apply is clicked, or (in principle) via `stopAllIntervalRefresh()`, which nothing in the current code path ever calls (see Known Quirks re: `TrackerComponent`'s commented-out lifecycle hooks).
- **`GtfsStaticStateService`** (`/home/kwongtn/rosak_firebase/src/app/tracker/services/gtfs-static-state.service.ts`) — holds `sources: { [key: string]: StaticGtfs }`, each with `isLoading`, and parsed `stops`/`routes`/`trips` GeoJSON collections, fetched once per source (no re-fetch/refresh loop). Mutated via `upsertSourceUrls()` (called from the same `StatusCardComponent.onApply`).
- **`GetGeojsonService`** (`/home/kwongtn/rosak_firebase/src/app/tracker/services/get-geojson.service.ts`) — stateless; a single `getData()` method called once by `TrackerMapComponent.ngOnInit` for the static rail-line overlay. No caching — a remount of `TrackerMapComponent` re-downloads/re-unzips the file from scratch.

All service state is purely in-memory (no persistence layer), scoped to the JS module/singleton lifetime — i.e. effectively "for as long as the SPA tab stays open," regardless of route navigation, since these are root-provided singletons rather than component-scoped providers.

## Permissions, Roles & Flags

- **Route guard**: none (disabled — see Path(s) & Routing / Known Quirks). Any visitor — anonymous or authenticated, any role — can load `/tracker` directly.
- **Nav-link visibility**: gated client-side only, on the Firebase custom claim `betaTester` (`app.component.ts:141-177`), via `AuthService.customClaims` (Firebase ID-token custom claims, populated in `/home/kwongtn/rosak_firebase/src/app/services/auth.service.ts`).
